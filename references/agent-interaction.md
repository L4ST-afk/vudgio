## 一、任务形态决定界面布局约束

在开始设计之前，首先明确用户的核心任务与操作对象，再决定会话气泡、结构化表单、工作台面板与产物画布之间的空间拓扑：（自研）

- 目标澄清与探索：适合通过流式对话推进，利用语言的灵活性迅速收敛模糊需求。
- 高频编辑与精确调参：必须提供 GUI 结构化控件（滑块、分段器、表单），避免用户陷入来回打字的低效沟壑。
- 产物消费与协同修改：当修改文档、代码或图形对象时，用户与 Agent 应共享同一份草稿与保存目标；在聊天气泡中给出的修改建议、预览视图中的临时渲染与最终落盘的对象必须具有清晰的视觉边界。（自研）
- 画布空间（Canvas）：适用于多对象关联或空间编排任务；当画布元素作为对话上下文时，必须有明确的高亮选中提示，杜绝让用户猜测 Agent 到底读取了全局还是局部。（自研）

## 二、用户对 Agent 的控制权可落实性（RICH 范式）约束

人机协作的核心在于维持用户的确定性信任。控制权必须体现在具体可操作的界面要素上：（自研）

| 委托原则 | 界面落地形态 | 核心核验标准 （自研）|
|---|---|---|
| 可见（Visible） | 当前任务标题、正在执行的步骤、受影响的目标文件 | 状态与后端真实事件严格绑定，无虚假演出动画 （自研）|
| 可解释（Explainable） | 关键决策依据、引用来源摘要、当前操作的作用范围 | 披露关键上下文与参数，不强行暴露模型冗长自语 （自研）|
| 可介入（Interruptible） | 编辑草稿、实时暂停、补充说明、修改后续执行队列 | 明确操作如何作用于正在运行或排队的任务 （自研）|
| 可收回（Revocable） | 终止任务按钮、回滚快照入口、撤销（Undo）机制 | “发出停止请求”与“已安全停止”必须严格分状态展示 （自研）|
| 可追责（Accountable） | 执行审计日志、Diff 差异比对、版本历史记录 | 用户可清晰追溯哪个工具在何时修改了哪个文件 （自研）|

> ⚠️ 边界：授权确认机制应依据操作的影响范围与可逆性灵活设计。只读查询自动放行；涉及文件删除、外部发布或写操作时，清晰呈现受影响对象与影响范围，而不是对每一步琐碎动作都弹窗打扰用户。

## 三、会话与任务的全生命周期状态流约束

每个交互状态都必须在界面上有清晰表达，并能明确回答以下问题：（自研）

| 交互状态 | 用户能看到什么 | 用户可进行的操作 | 异常时保留什么 （自研）|
|---|---|---|---|
| 草稿态（Drafting） | 输入框、已附带的上下文 Chip、参数设置 | 自由打字、拖入文件、随时清除 | 切换会话或临时中断时草稿自动暂存 （自研）|
| 已受理/排队中（Queued） | 任务已被系统接收的微弱指示、排队位次 | 允许即时撤回或取消排队 | 未开始执行前撤回无任何副作用 （自研）|
| 执行运行中（Running） | 正在执行的子步骤标签、流式文字渲染、已完成步骤打勾 | 可随时点击「停止/中断」按钮 | 中断时保留已生成的部分输出与已确认产物 （自研）|
| 等待授权（Pending Approval） | 工具调用卡片、拟执行命令、受影响参数高亮 | 允许、拒绝、提供补充指令 | 超时或拒绝后任务优雅暂停，不崩溃报错 （自研）|
| 已完成（Completed） | 结构化最终结论、生成的产物卡片（Artifact） | 查看、一键复制、在外部打开、基于结果继续对话 | 完整记录沉淀在历史流中，可随时回溯 （自研）|
| 失败/停止（Failed/Aborted） | 明确的错误根因、已中断的断点标记 | 一键安全重试、修改参数后重试 | 错误依据与已生成的阶段结果完整保留 （自研）|

## 四、对话、过程、工具与产物的正交分层约束

现代桌面 Agent 界面严禁将所有内容挤压在一个冗长的单列气泡流中：（自研）

1. 主对话层（Conversation Layer）：承载用户的原始意图表达与 Agent 的最终结论回复。
2. 思考与过程层（Reasoning & Process Layer）：（自研）
   - 采用可折叠的时间轴（Reasoning Timeline）。
   - 在流式生成时展示简明的阶段标签（如“正在检索相关代码...”），生成完成后收拢为轻量摘要，不占用首屏主视线。
3. 工具执行卡（Tool Execution Card）：（自研）
   - 将每一次工具调用的发起、参数输入、执行状态与返回结果封装在同一张独立卡片内。
   - 严禁每个事件零散打印一行系统文本。
4. 产物层（Artifacts / Workspace Layer）：（自研）
   - 生成的大段代码、Markdown 报告、交互原型或设计稿独立开辟在右侧或专用工作台面板中。
   - 支持独立滚动、版本切换、本地保存与全屏放大。（自研）

## 五、多会话与多线程桌面管理约束

在桌面端多任务场景下：

- 线程切换隔离：当用户在侧边栏切换不同任务线程时，各线程的未发送草稿、附件上下文与运行中任务必须严格隔离并持久化，切勿因组件卸载导致输入内容丢失。
- 后台任务可观测：在后台线程运行的任务，若进入等待授权或出错状态，在侧边栏对应条目上需有轻量状态红点或徽章提示。
- 连接恢复与幂等性：断网或重开窗口后，优先拉取服务端权威快照恢复界面，禁止在前端无脑重放可能具有破坏性副作用的操作请求。（自研）

## 六、决策负荷收敛、信息秩序与文案克制原则约束（Decision Friction & Copywriting）

在桌面 Agent 界面中，过多的判断阻断与冗余文案是摧毁用户体验与界面秩序感的头号杀手：（自研）

### 尽量减少交互阻断（Minimize Decision Friction）

- 不要把系统推断复杂度甩给用户：优先自动承担可推断的默认行为，避免在主任务流中频繁弹出非必要的二次确认或技术分支选择。
- 就近决策原则：当必须由用户做出判断时（如权限授予、冲突覆盖、敏感产物采纳），选项必须自然放置在用户本来就打算做选择的上下文区域（如当前卡片底部或正在聚焦的输入条），严禁突兀弹窗打断主视线。
- 信息优先级与秩序重组：重新审视页面中包含的所有功能和组件。明确区分高频主动作（P0）、高阶配置项（P1）与历史归档（P2），运用折叠组、分段器或抽屉进行秩序化重构，消除散乱平铺。（自研）

### 杜绝冗余解释性描述（No Redundant Explanations）

- 严禁弄脏界面：禁止在卡片、面板与表单中随意添加冗长说明、占位副标题或所谓的“操作指引”。这些说明文字不仅破坏了界面的视觉纯净度，还会严重浪费用户的注意力。
- 让布局本身说话（Let the layout do the explaining）：依靠清晰的视觉层级、合理的组件间距与明确的操作意图来传达功能，只有在涉及高风险不可逆破坏性后果时才允许添加简明警示。（自研）

### 界面文案审查标准（Tone, Style & Concision）

1. 契合受众：文案语气必须贴合当前界面的目标人群，容易理解、表意明确，但切忌轻浮或过于口语化。
2. 严丝合缝的长短匹配：文本长度必须严密适配其承载控件（如按钮、标签、弹层）的物理尺寸，严禁出现因文字过长导致的尴尬截断或多行换行。
3. 禁止随意造词：使用行业通用的标准术语，严禁生造晦涩自创黑话或中英夹杂的拼凑词。
4. 彻底禁用中点分隔符：界面文案与标签中严禁使用中点 “·” 作为分隔符。若历史代码中存在，必须彻底移除，改用合理的 CSS 布局留白（如 `gap`）、背景阶梯色块或微弱的极细分隔线。（自研）

## 七、达成判据与三态结论

下列判据可直接用于验收，每条带可执行的检查点：

| 判据 | 检查点 / 命令 | 阈值 |
|---|---|---|
| 流式对话探索 | 检查目标澄清与探索是否通过流式对话推进 | 已通过流式对话 |
| GUI 结构化控件 | 检查高频编辑与精确调参是否提供滑块、分段器、表单 | 已提供 |

| 状态与后端绑定 | 检查可见原则下状态是否与后端真实事件严格绑定 | 严格绑定，无虚假演出动画 |

| 就近决策 | 检查选项是否自然放置在用户本来就打算做选择的上下文区域 | 已就近放置 |
| 严禁突兀弹窗 | 检查是否严禁突兀弹窗打断主视线 | 严禁 |
| P0/P1/P2 重构 | 检查是否运用折叠组、分段器或抽屉进行 P0/P1/P2 秩序化重构 | 已重构 |
| 严禁冗余说明 | 检查是否禁止在卡片、面板与表单中随意添加冗长说明 | 严禁 |
| 让布局说话 | 检查是否依靠视觉层级、组件间距与操作意图传达功能 | 已依靠 |
| 高风险简明警示 | 检查高风险不可逆破坏性后果时是否只允许添加简明警示 | 只允许简明警示 |
| 文案契合受众 | 检查文案语气是否贴合目标人群 | 已贴合 |
| 长短匹配 | 检查文本长度是否严密适配承载控件物理尺寸 | 已严密适配 |
| 禁止造词 | 检查是否使用行业通用标准术语、严禁生造黑话 | 已使用标准术语 |
| 中点分隔符禁令 | 检查界面文案与标签是否使用中点 “·” | 严禁使用 |

三态结论：每条判据分为「过 / 不过 / 证据不足」。缺画面或缺材料一律记为「证据不足」，不得直接判「过」。
