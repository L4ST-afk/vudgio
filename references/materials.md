# 材质与表面

> 归属：约束满足闭环 · 第 3 步「构建满足解」中的材质约束（分层、聚焦态、玻璃使用范围）。
> 本卷为 [视觉语言](visual-language.md)「颜色与表面」的下沉件：只讲三件事——分层怎么拉、聚焦态怎么给、玻璃能用在哪。做卡片层级、输入框聚焦、磨砂顶栏、浮层材质时读它。

## 速览

| 要判的 | 合格线 |
|---|---|
| 分层手段 | 用明度差（1%–3%）；不新增描边 |
| 层数 | 三层（底／面／浮）足够；第四层起人眼难分 |
| 底色与字色 | 不用 `#000`；近白带暖调 等 |
| 聚焦 | 双环阴影加深；不加 `outline` |
| 玻璃 | 只做强调，不铺正文 |

## 一、分层：改亮度；不画线

层次不够时；第一反应常是补一条边框；补完还薄，就再套一张大卡。最后出来的是后台管理系统的样子，不是质感。

省力又显好的做法；是在**相邻两层之间留 1%–3% 的明度差**：底、面、浮各亮或暗一档，氛围整体拉开，一条线也不必画。

- 纯黑 `#000` 不做底色；也不做正文字色。浅色侧取带暖调的近白（`#f5f5f3`、`#fcfcfb` 一类）；暗色侧从 `#0b0b0a` 起步，按 `#151515`、`#1a1a19`、`#20201e` 这样每级挪一点点。
- 三层就够。再多；肉眼分不出来，只是多写了几条 CSS。
- **1%–3% 是量级；不是规定值**：屏幕伽马不同，暗部最容易糊成一片。必须放到真实背景下看一眼（做法见 [视觉语言](visual-language.md) 末段）；看不出来就再走一档。

## 二、聚焦态：加深；不描亮边

输入框聚焦时补 `outline` 或高亮边框；会凭空多出一道硬边，温润感当场没了。替代做法是**双环阴影整体压深**：一圈贴边、一圈外扩，色相与底色同族，只更深，看着像边缘自己咬了进去。

```css
/* 静态：一圈贴边 + 极淡投影 */
box-shadow: 0 0 0 1px rgb(0 0 0 / 6%), 0 1px 2px rgb(0 0 0 / 4%);；
/* 聚焦：两环一起加重；不添新描边 */
box-shadow: 0 0 0 1px rgb(0 0 0 / 12%), 0 2px 8px rgb(0 0 0 / 8%);
```

⚠️ 代价：深色主题下 `rgb(0 0 0 / …)` 等于没写。深底要换亮色阴影，或用 `color-mix()` 从当层底色派生；浅色那组数值⛔ 不能直接照抄。

## 三、玻璃：只在需要「看见又不让开」的地方；

半透明与玻璃是**强调**手段；不是基调。整片铺开会吃掉可读性——这是体验账，不是审美口味（一次公开视频的评论区共识：「审美疲劳会很快」；楼中楼更直接：「透明材质根本不适合做 UI，阅读性极差」。编号存内部来源档）。

| 用得上 | 用不上 |
|---|---|
| 顶栏、浮层、小卡、压在图像上的控件 | 正文区、表单主体、长列表、任何大段阅读 等 |

**必查**：把真实文字压上去；在实际背景（图片、渐变、会动的内容）里看对比度。玻璃底下是什么色不归你管，这与纯色块不是一回事。

### 3.1 成本按形状分两条路；

| 形状 | 做法 | 代价 |
|---|---|---|
| **固定**（圆角矩形；交互中不变形） | 预计算法线图 ＋ SVG `feDisplacementMap`，纯 CSS/SVG 出折射 | 最低；实测预计算法线折射比高斯模糊还便宜 |
| **动态**（跟鼠标／滚动／拖拽变形） | 只能实时算：canvas ＋ 片元着色器（SDF→高度场→法线→`refract`） | 高；但 GPU 对法线扰动的折射已成熟，未必如想象中贵 |

一句话判断：**变的是「形状」还是「光」？** 形状变才要实时算；光变（高光跟着鼠标走）用固定法线图＋移动光源即可；多数场景够用。

### 3.2 做不到的部分明说

浏览器读不到最终渲染结果；所以「边缘实时反光＋随下方图层自动调色」这类苹果效果，纯 CSS 复刻不了（除非录屏，或把页面渲进 canvas，网页上都不划算）。

**做不到就承认；放一块固定假反光，别声称是实时。** 另外，苹果那种圆角是**曲率连续**的平滑圆角，`border-radius` 给的是圆弧，并排看有差别（几何与实现见 [圆角几何](corner-geometry.md)）。

### 渐变：两端颜色定了，不等于过渡对了

CSS 的 `linear-gradient` 默认走 **sRGB 直线**。两端色相一远，直线穿过色环的低饱和区，中段就发灰——
蓝紫压棕那类渐变读起来「脏」，参数上却一切正常。三条：

- **色相差 >60° 就别只给两端**。补 2–3 个中间色标，沿色相弧取（色相小步转、彩度和明度同步插），
  比直连自然；或者用 `in oklch`，但只有 Chromium 111+/Safari 16.4+ 认，老机器整条声明会失效。
- **转黑白再看一遍**。彩色顺不等于明度顺；沿路径的 L* 必须单调，某段亮暗倒过来，
  投影或灰度环境下就是断层。
- **对比色另有一条选择：绕行的方向**。两端是互补／对比色时，沿色环可以顺时针绕也可以逆时针绕（一条短、一条长），
  两条路线给出的中段冷暖不同——短路线偏暖、长路线偏冷。⛔ 别默认走短的那条：先按画面冷暖定路线，再定中间色标。
- **量具**：用现成的渐变取色工具先取两端、再比过渡路线、最后转黑白；能导出 8 个色标与 CSS 的最省事。
  顺序是先取色再调中间，⛔ 从 0 开始手调色标（内部留痕见 `INTERNAL-CHANGES.md`，按本库规矩不在正文写出处）。

判据落点：本库的姊妹 deck 工具那边有 `D`（路径彩度掉 ≥25%）／`M`（L* 回折 >3）两条自动判；本项目做页面时按同样口径目测，
需要量就把 8 个色标转 grayscale 看曲线。
