# 显式探索与比较

> 归属：约束满足闭环 · 第 2 步「定达成判据」中的多约束解显式比较员。
> 本卷只定「什么时候、怎么比较多个约束满足解」：本流程只在用户点名要比方向、比改动档位或比版式时才走。它是叠在新建、重设计、存量任务之上的一层，不顶替各自的产品事实、锁定范围、制作与验收规则；领域模块只出方法，⛔ 自己加候选数量、也⛔ 重启一轮选择。约束候选解不是必经阶段，只是约束的一个可选解空间。

数量先服从用户；用户没有指定数量时才默认三个。比较改动档位时保留现状基线；比较版式时保持选定约束的字体、色彩和控件语法，只改变骨架、主视觉摆法和页面结构。内部概念、草图和素材候选的数量不随对外方案数量减少。

## 先用文字收敛

先沿主入口确定基础任务与适用的领域规则；按它要求的方案产物形成所需数量的对外方案。基础路径要求通用方案流程时，才按 [设计方向](design-direction.md) 完成产品事实、删减、概念、主视口灰度和过关检验。每个方案都必须适配且可落地，不靠极端颜色或构图制造差异，也不拿陪跑方案凑数。骨架按需读 [说服型骨架](direction-persuasion.md)。

**拉开差异要写具体轴**：只说「随机、独特」没有用，模型会交回同一套配色的三张左右布局，只把圆角矩形换成圆环图标。每个方案在候选说明卡里逐条写明三轴取值：字体（衬线／无衬线／等宽／混排）、版式骨架（居中对称／非对称偏心／满版压字／网格拼贴／递进分栏）、色彩家族（主色相＋明度区间＋底色冷暖）。三轴里有两轴相同，算同一方案的两个变体，占不满一个候选位。

「大胆排版、打破居中对称」可以写进骨架那一栏，用在说服型和阅读型页面：元素贴边、留白不对称、标题跨栏。操作型界面（后台、表单、数据密集页）不拿它当卖点，骨架服从扫描路径；型怎么判见 [Skill 主流程](../SKILL.md) 的「这块面是什么型」。

先用三四行写清每个方案的感觉、首屏、核心动作、字体、色彩和主视觉，附推荐及理由，再问用户：直接按其中一个做，还是把几个方案做成首屏摆一起比。发出去这轮就收。用户从文字就能定、或早说清要什么，那只深化选中的一个，⛔ 再出对比页；要看真实画面才好定，才做多个首屏。

只交付设计说明时止于候选说明卡，并说明未渲染。用户已经给定参考图、品牌规范或明确风格时，所有方案都留在这个风格里，只在骨架、主视觉和页面结构上拉开。

## 用户要看实际画面

按 [风格对比页](style-explorer.md) 把各方案首屏放在一起。一个方案对应一个 HTML 文件、一个视口，只出首屏和主状态，⛔ 提前铺成好几个完整页面；交互、响应式、动效一概不写，也不取证、不派画面评审。宿主支持并行制作时按方案分工，不让多个执行者同时修改同一份共享样式。

- 各方案共用同一份产品事实和示例数据，只写一次；结构、样式、标题、副标题和主视觉各写各的，不用同一模板换几组样式凑数。
- 主视觉要靠图的方案，照 [素材](media.md) 出一张，最多重做一次；页面本身就带专项候选流程的走专项，⛔ 另开一批生成。剩下的图位先拿从页面取色的色块顶着。
- 候选目录一次截完，缩略图和并排总览 `sheet.png` 一起出齐；主 Agent 亲眼看一遍，只动重叠、裁切和肉眼可见的粗糙处，再交付。
- 附上推荐理由，请用户选定方案并说清喜欢和不喜欢的具体地方，这一轮就结束。

用户说“你定”“直接做”或无人值守时，不再追问、自己定，但候选也只在明确要探索时才做。把截图统一缩到 480px 宽并排比一次，写明为什么选它，然后只深化那一个。

## 比较版式

先用文字写出两三种骨架的差别；能从文字选定就只做一个，要看实际画面再做成首屏，连同选中的方案放进对比页。用户只回复选哪个，就并入意见直接做完整页面；想拼合两个方案时，先做出拼合后的首屏给用户确认。
