## 一、起点说明

本章聚焦桌面 Agent 应用的核心组件工程实现与交互动效物理规范，涵盖自适应输入框、流式消息跟随、工具卡片状态机与性能优化。（自研）

## 二、智能输入框（Composer）工程实现约束

输入框是桌面 Agent 的操作起点。必须先明确草稿、附件上下文、发送、排队与中止的状态归属，再处理视觉过渡。（自研）

### 自适应高度与“果冻”弹性扩展配方约束

为了在用户连续输入或粘贴多行文字时提供顺滑平稳的视觉体验，推荐采用三层高度自适应机制：（自研）

1. 核心内芯（Inner Textarea）：现代 Chromium 内核直接使用标准 CSS `field-sizing: content`，让 textarea 实时无缝跟随文本量扩展；兼容环境可在外层通过轻量 `ResizeObserver` 监听内芯真实高度。
2. 外容器过渡（Outer Wrapper）：外层容器显式计算 `height` 并绑定弹性过渡曲线（Spring 或 Bezier 缓动）；外容器必须保持 `overflow: visible`，允许内芯在自适应增高瞬间平滑探出，避免内容被瞬时裁剪；增长阶段与收缩阶段使用非对称缓动（输入增高时响应迅速，退格收缩时回弹柔和）。
3. 滚动上限与局部滚动条收敛：设定明确的 `max-height`（如 240px~320px），超出后外层高度锁定，内层 textarea 开启垂直滚动；去除系统灰色滚动条外观：通过局部样式（`scrollbar-width: none` 及 `::-webkit-scrollbar { display: none }`）消除粗糙的系统滚动条，同时完整保留滚轮、触控板手势、文本选中与键盘导航功能；严禁全局隐藏滚动条，仅限定在 Composer 输入框内。

### CJK 输入法（IME）安全发送契约约束

- 必须配合 [手册导读](open-claude-manual.md) 中的 500ms 时间戳守卫：拦截在选词确认时伴生的冒充 Enter 击键。
- 拦截伴生键后立即复位时间戳，确保后续普通按键畅通无阻。
- 换行统一支持 `Shift + Enter`（支持配置 `Ctrl/Cmd + Enter` 发送）。
- 附件上传状态细分：正在解析、上传成功、错误重试与已移出上下文。（自研）

## 三、流式消息输出与用户视口跟随策略约束

在桌面大屏上，模型流式吐字速度极快，如果简单地使用 `element.scrollIntoView()` 暴力滚动，会导致试图向上翻看历史记录的用户被强制拉回底部，引发极度挫败感。（自研）

### 视口智能跟随算法约束

1. 自动跟随状态判定：计算容器滚动位置与底部的物理距离：`distanceFromBottom = scrollHeight - scrollTop - clientHeight`；设定容差阈值（如 `threshold = 40px`）：当 `distanceFromBottom <= threshold` 时，认为用户处于“底部跟读模式”，新流式文字或工具卡片追加时平滑保持贴底；当 `distanceFromBottom > threshold` 时，判定用户正在“向上回溯阅读”，立即冻结自动滚动，保持当前阅读视口内容绝对静止。
2. “回到底部”悬浮按钮：当用户处于回溯阅读模式且下方有新消息生成时，在右下角悬浮轻量按钮（如“有新回复 ↓”），点击后平滑滚动回底部并重新激活跟随。
3. 内容高度突变防抖：代码块高亮完成、异步图片加载、折叠面板展开时，计算高度变化差值并补偿 `scrollTop`，防止页面发生视网膜级别的抖动。

## 四、工具、审批与产物组件规范约束

| 组件类型 | 核心状态职责 | 严防错误 （自研）|
|---|---|---|
| Tool Execution | 调用标识 ID、输入参数、执行中进度、成功结果或错误原因 | 每个事件零散打出一张卡；将接口已受理直接误标为已执行完成 （自研）|
| User Approval | 拟执行操作、影响范围、目标文件列表、允许/拒绝动作 | 只问“是否同意”，不展示具体受影响的文件路径或命令 （自研）|
| Plan / Roadmap | 总体步骤清单、当前进行中步骤、已完成步骤 | 将模型文本里的 `- [ ]` 错当成系统执行证据 （自研）|
| Artifact / Diff | 代码/文档差异、单向合并、整文件预览、一键导出 | 预览成功直接误判为本地文件已写入落地 （自研）|

有真实耗时的状态（工具调用、录音、上传、转码）按同一套收尾：进度与计时贴真实时长走，结束换成静态终态（成功、失败、已取消三选一）；⛔ 用循环动画冒充「正在进行」，也⛔ 在结束后继续呼吸或扫光。失败就停在失败态并说清原因，⛔ 悄悄转回去重试。

### 拒绝与拦截：停住、留底、给出路

审批被拒、权限不足、范围拦截，都不是「任务输了」，而是一次需要人介入的暂停。

- **拒绝＝暂停，不是终止。** 被拒或权限不足时，这一轮停住但保住上下文：卡片上留着「已做到哪一步」，并写明「我还需要什么才能继续」；用户补充的信息回到同一会话续做，⛔ 一拒就判任务失败、清空流程、让人从头再来一遍。
- **拦截要给出路。** 权限或范围拦下时，说清两件事：为什么拦（哪条规则、哪条数据边界）、哪里可以（私下渠道、换个人问、缩小范围、去掉哪项再试）。⛔ 只写「无权访问」「操作被阻止」——用户只能自己猜该换什么。
- **异步结果落同一处。** 定时提醒、后台任务完成、审批回执，全落进同一个收件箱或待办视图，标清来源与时间；⛔ 用一连串系统通知散着弹、⛔ 只在各页角落的角标里报。
- 空间切换要有一句话说清「现在看到的是谁的数据」：个人空间与团队共享空间切过去时，标题或副标题写明归属，⛔ 在共享面板里露出个人数据。
- 验收：拒绝一次看流程是否还在原处、拒绝文案里有没有可行路径、定时提醒与后台完成是否落在同一列表、切到共享空间后个人数据是否还在视野里。

## 五、可拖拽分栏与多面板工作台约束

在对话与产物并排展示的双栏或多栏布局中：（自研）

- 分栏宽度拖拽手柄必须具有清晰的 hover 与 active 视觉反馈。
- 折叠吸附与 Escape 取消闭环：拖拽至左右极限（如 ≤18% 或 ≥82%）时支持自动吸附；若在拖拽中途按下 `Escape` 键，必须安全复位状态机并保留拖拽前基准宽度（`previousRatioRef`），严防手柄 DOM 丢失死锁。
- 左右面板必须拥有完全独立的滚动容器，严禁产生跨面板的全局水平滚动条。（自研）

## 六、动效设计物理学与空间关系约束

交互动效应当为用户传递界面状态与空间因果关系，拒绝为了修饰而无故添加冗余动画：（自研）

1. 动效目的优先：确认用户动作（点击即时响应反馈）；提示状态迁移（从草稿态收缩进入运行态）；表达空间来源（侧边栏抽屉从物理边缘划入）；维持对象连续性（小卡片平滑展开为大工作区）。
2. 阻尼与弹性标准：浮层展开与微交互偏好轻微有阻尼的 Spring 物理曲线；避免过度过冲（Overshoot）导致界面晃动与视觉眩晕；必须支持用户中断与快速连续击键，动画执行期间不能阻塞正常交互。
3. 系统级无障碍适配：监听媒体查询 `@media (prefers-reduced-motion: reduce)`；当用户系统开启减弱动态效果时，瞬时切换状态或使用极简透明度渐变，严禁出现大幅位移与缩放。

## 七、视觉几何学、边框与字号规范约束（Visual Geometry, Borders & Typography）

桌面 Agent 界面对精致度与信息密度的要求极高，必须落实精确到半像素的几何物理学与字体约束：（自研）

### 同心圆圆角计算（Concentric Border Radius）

- 问题根因：嵌套容器若内外两层使用相同的 `border-radius`，由于内外边距的挤压，内层四角会出现视觉变形，内外弧度无法保持同心平行，造成明显的粗糙感。
- 同心圆黄金公式：`R_inner = max(0, R_outer - padding)`
- 典型配方：外层卡片 `border-radius: 12px`、内边距 `padding: 8px`，则内部嵌套项的圆角必须严格设为 `4px`；当 `padding >= R_outer` 时，内层元素应采用直角或至多 `2px` 微圆角。

### 光学对齐（Optical Alignment）

- 严禁单纯依赖 CSS 的几何包围盒（Bounding Box）进行机械贴边或居中。
- 对不对称图形（如播放三角形、返回箭头、外凸徽标）、大写英文字母与图标混合编排时，必须依据视觉质心（Visual Center）施加 1px 级别的光学补偿，确保肉眼感受平衡。（自研）

### 0.5px 精细微边框标准（Hairline Borders）

- 现代高分辨率（HiDPI / Retina）桌面显示器下，传统的 `1px` 边框在深色主题或多面板下显得厚重、粗笨并割裂视线。
- 界面上的分割线、卡片外边框、标签描边统一采用 `0.5px` 边框标准。
- 实现方式：现代 Chromium / WebKit 直接支持 `border: 0.5px solid var(--border)`；或采用内嵌微阴影 `box-shadow: inset 0 0 0 0.5px var(--border)`，确保在各种缩放比率下保持极致纤细与现代感。

### 字体层级收敛法（Typography Hierarchy）

1. 全页字号阶梯严禁超过 4 种（推荐 3 种）：推荐桌面标准阶梯：辅助微文本（`12px`）+ 正文/输入（`13px` 或 `14px`）+ 顶栏/模块标题（`16px`）。
2. 最小可用尺寸硬性门禁 12px：严禁在界面任何位置使用小于 `12px`（如 10px、11px）的文字，杜绝在低 DPI 屏幕上字体渲染发虚模糊、损害可读性。
3. 多维表达主次关系：严禁为了突出某行内容盲目创造第 5 种字号；必须优先通过字重阶梯（400 常规 / 500 中粗 / 600 粗体）、字体灰阶/透明度对比（主色 / text-muted / text-subtle）以及空间外边距（Whitespace）构建层级秩序。

### 圆角与阴影的克制使用

- 坚决杜绝无功能意义的装饰性圆角和扩散大阴影。
- 圆角与阴影必须严格服务于界面的物理层级（基底卡片低阴影或无阴影、浮层 Popover 中阴影、模态弹窗高阴影）。
- 严禁使用“卡片左边缘带颜色的粗线条”这一过时的装饰性反模式，避免使页面碎片化并弄脏视觉。（自研）
