## 反例

两种情况最常见：一是从一个好看的截图里手抄 `#3b82f6`、`#1f2937`，再手调三档，调完 400 比 500 还深——色阶彼此漂了，没人能复原；二是项目根本没有令牌，模型就默认 indigo + gray，页面一看就是生成器产物。（错误原文保留）

规则：**值必须来自系统，⛔ 不手调 hex**；没有系统就先生成一套，再声明它是这一次生成的。

## 先检测（Step 0）

一个来回就能查完，⛔ 凭印象：框架与渲染方式（SSR/SPA）／Tailwind 大版本（v4 `@theme`、v3 `tailwind.config.js`）／已有 tokens 与主题文件／组件库（shadcn/ui 等自带令牌契约）／暗色是已有、计划还是无。没读到就写「未读到」。

**既有系统永远优先。** 把原则翻译成它的词汇，⛔ 覆盖、⛔ 静默迁移、⛔ 引入用户没要的构建依赖。（库名 `shadcn/ui` 不改）

## 三级解析顺序

任何一个具体值，按这个顺序取：

1. 项目已有令牌（Step 0 读到的）
2. 本次生成的令牌（本卷算法 + `scripts/emit_tokens.py`）
3. 书的默认刻度——**并且必须在交付说明里写明降级**

脚本名 `scripts/emit_tokens.py` 不得改动。

三级都取不到，这个缺口本身就是发现：项目缺一个令牌，先补它，否则同类决定会各写各的。

## 十类令牌

| 类 | 刻度 | 约束 |
|---|---|---|
| 色阶 | 100–900（可加 50/950） | 相邻级差 ≥25% 感知步距；色相旋转单步 ≤20°、整条累计 ≤30°（见「色板级判据」） |
| 文字色 | 深 / 灰 / 浅灰，最多三档 | 灰字不上彩底；要的是降对比，不是变灰 |
| 间距 | 4/8/12/16/24/32/48/64 | 组内紧于组间；一处距离只由一层加 |
| 字号 | display / h1 / h2 / body / caption | 相邻级差 ≥25%，⛔ 15/16/17 挤在一起 |
| 行高 | 随行宽与字号 | 窄 1.5 → 宽 2；大字可到 1 |
| 圆角 | 4/8/12/16 | 同心：内 = 外 − 内边距；⛔ 圆角套圆角 |
| 边框 | 1px 常规、0.5px 分隔 | 同类线全页只出现一次 |
| 阴影 | 最多 5 级 | 都带偏移 + 柔化；靠明度 1–3% 分层，不靠加描边 |
| 缓动 | out / in-out / drawer 三条 | `cubic-bezier(0.23,1,0.32,1)`、`(0.77,0,0.175,1)`、`(0.32,0.72,0,1)` |
| 时长 | press 100–160 / tooltip 125–200 / popover 150–250 / panel 200–500 | UI 元素 <300ms，整页转场除外 |

刻度、数值、阈值、⛔ 禁令、**不得改动**。缓动三条的 `cubic-bezier` 参数值不得改动。

## 动效令牌

缓动与时长的值同样来自系统，⛔ 逐个组件现场挑：

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);      /* 进入 */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);  /* 来回 */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);   /* 抽屉、面板 */
--duration-press: 160ms; --duration-tooltip: 200ms;
--duration-popover: 250ms; --duration-panel: 400ms; --duration-page: 500ms;
```

CSS 变量名与取值**不得改动**（字段名保留）。

`emit_tokens.py` 写出的 `theme.css`（Tailwind v4 `@theme`）里同样带这三条 `--ease-*`：v4 的 `ease-*` 工具类就是从 `--ease-*` 命名空间取名，写 `class="ease-out"` 和写 `var(--ease-out)` 落的是同一条曲线。Tailwind 项目里因此没有「顺手挑一条」的借口——命名空间已经给到。没有 CSS 变量的宿主（SwiftUI、Framer、原生 App），把同一组参数抄成一份原生常量表，⛔ 逐处手填。

**有弹簧手感就要有曲线文件，⛔ 靠感觉写 `cubic-bezier`。** 按目标时长反解，命令直接吐 CSS：

```bash
python3 scripts/spring_to_linear.py --target 200 --overshoot 8   # 200ms 落定、过冲 8%
python3 scripts/spring_to_linear.py --preset 咔嗒 --json         # 复现材质手感
```

解出来的曲线存成令牌再引用（如 `--ease-spring-settle: linear(...)`），⛔ 把 `linear(...)` 原样贴进组件样式——那等于把弹簧退回成一次性的手填。

脚本名 `scripts/spring_to_linear.py` 与参数 `--target` / `--overshoot` / `--preset` 不得改动。输出 `linear(...)` 与一条 `cubic-bezier` 退路（不支持 `linear()` 的浏览器用）。⚠️ 手感表里的 k/c 是**材质倾向**，不是时长：咔嗒档积分出来落定约 0.93s，已越过「界面元素 <300ms」，所以按钮上要的是 `--target`，不是 `--preset`。（数值 0.93s / 300ms 不得改动）

**减少动态效果**（凡是位移、缩放或滚动超过 20px 的地方都要带）：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 1ms !important; transition-duration: 1ms !important; }
  .reveal { opacity: 1 !important; transform: none !important; }
}
```

媒体查询名 `prefers-reduced-motion` 与类名 `.reveal` 不得改动。

**参数层有没有被绕过，跑体检**：`python3 scripts/motion_audit.py --root <项目目录>`。它查的七条都对应上面已有的禁令（`transition: all`、`scale(0)`、单向 `ease-in`、字面量 `cubic-bezier`、字面量时长、动布局属性、有过渡却缺 `prefers-reduced-motion`）；退出码 1＝有发现，`--json` 给标记卡草稿（字段与 review-animations 的 `MARKER-CARD.md` 对齐）。它只做静态定位，⛔ 不代替渲染验收；报出来的东西仍要人看一眼才算数。内容与操作一样不少，只是直接到位；⛔ 用它把需要的信息藏起来。（⛔ 禁令）

## 生成色阶（禁手调）

算法顺序固定，顺序错了色阶就不匀：

1. 定基色 500
2. 定两端 100（最亮）与 900（最暗）
3. 二分出 700 / 300
4. 再二分出 800 / 600 / 400 / 200
5. 每级：饱和度随明度离 50% 变远而抬高（让彩度看起来稳定）；色相朝亮端 60/180/300 或暗端 0/120/240 旋转——**单侧端点偏移 ≤20°（500→端点 4 级线性，等价 5°/步），整条色阶 100↔900 累计 ≤30°**
6. 灰阶带温度（冷 220°、暖 35°），两端各做补偿

数值 100/900/700/300/800/600/400/200、硬帽 20–30°（= **单侧端点** 20° / **累计跨度** 30°）、冷 220° / 暖 35°，改的人必须同时写明三件事才能动：它是单侧端点还是相邻步进、标定依据是什么、折点验收跑过没有（见下）；⛔ 不许把「单步」读成相邻两级——那是另一个量，差一个数量级。

> **为什么要拆成两个封顶**（2026-11-20 实测补）：只封单步不管累计时，亮端 +20° 与暗端 −20° 会相加，两端差到 40°，整条色阶读成两个色族。
> 实测四条 base 的累计漂移：黄 `#eab308` 34.8°、蓝 `#2563eb` 31.7°、青 `#0f7b6c` 19.8°、红 `#dc2626` 18.0°——前两条越界，后两条没事，
> 说明「单步封顶」在真实输入下根本不约束累计量。现在 `--cap-total`（默认 30）超过就等比压回，单步仍封 20°。

> **封顶时整侧按比例压，⛔ 不逐级硬夹**（2026-11-20 补，外部评审逼出来的）：逐级夹会把端部几级压成**同一个偏移**——
> 蓝 `#2563eb` 的 100 与 200 同是 −20°，转出来的色相 204.0 与 207.9 甚至反向；红 `#dc2626` 的 100/200/300 三级同顶 +20°。
> 现在两道闸都按比例：某侧最大偏移超 20° 就整侧乘 `20/max`，两端跨度超 30° 再整条乘一次，比例与级序无关。
> 派生的判据：**同一侧既然在转，相邻级色相就不许差 <1°**——旧实现会红（`audit_palette.py --tokens` 的「色相停级」与 `test_no_hue_stall_at_either_end` 就是这条的闸）。

> **20° 到底是什么**（2026-11-20 第二轮外部评审定案）：20° 是**单侧端点预算**，不是步进帽。500→端点共 4 级线性分配，端点 20° ≡ **5°/步**；真实输入的自然相邻步进最大只有 14.1°（红 400→300），所以按「步进 ≤20°」读，这道闸几乎永不触发——上一轮评审据此提议「收到 5° 或删掉」，实为把「5°/步」误当「5°/端点」，照办会把红浅端 56.4° 削到 5°（−91%）、蓝浅端 38.6° 削到 5°（−87%），色阶退成同色相的不同明度，彩度稳定这个目的整个失效。⛔ 结论：数值不动，改的是读法。
> 标定依据：基本色相扇区约 60°，端点 ≤20°（约 1/3 扇区）保每级仍读作基色同族，4 步即 ≤5°/步；累计 ≤30°（半扇区）保两端不跨出色名；30 = 2×15，两侧同时吃满时总闸把各侧压回 15°，两闸不打架。
> 可证伪验收：扫一串自然端点 E，输出端点必须恰好 = min(E, 20)、曲线只在 20 处折一次（`test_endpoint_fold_at_cap`）；跨度同理写同一个系数（`test_total_budget_scales_uniformly`）。两条一起跑，阈值就不再是装饰。
> 若只能留一条：留单侧、取 **15°**——单侧 15 必然使跨度 ≤30，总闸的坏情况被完全覆盖；反过来只留跨度 30，单端仍可漂 30°（半个扇区），端点会被读成另一个色名。四条 base 在 15° 下跨度 28.8／27.8／15／23，全过。现值仍取 20／30（比 15 宽松，留住深色底的补偿余量）。

```bash
python3 scripts/emit_tokens.py --base '#0f7b6c' --name brand --out tokens/ --extended
python3 scripts/emit_tokens.py --grey --temperature cool --name neutral --out tokens/
```

脚本名 `scripts/emit_tokens.py` 与参数 `--base` / `--name` / `--out` / `--extended` / `--grey` / `--temperature` 不得改动。写出 `tokens.css`（CSS 变量 + 动效令牌）、`theme.css`（Tailwind v4 `@theme`）、`tokens.json`、`DESIGN.md`（配色/字体/字号/圆角/间距五要素）。输出文件名不得改动。基色必须是项目真色，⛔ 拿示例色当答案。（⛔ 禁令）

## 色板级判据（成套门，2026-11-20 增）

对比度门只判「一对前后景够不够」，判不出「这一整套色在一起好不好用」。成套的问题单独一道门：

```bash
python3 scripts/audit_palette.py --tokens tokens/tokens.css          # 色阶族：累计漂移 + 明度单调
python3 scripts/audit_palette.py --palette palette.json --json       # 角色板：文字/填充/强调色
```

两个作用域，两套阈值，**⛔ 不得互相挪用**（数值重叠但判的不是一件事）：

| 作用域 | 判什么 | 阈值 | 越界后果 |
|---|---|---|---|
| 色阶内部（同族 100↔900） | 旋转补偿是否过头 | 单侧端点 ≤20°（≡5°/步）、累计 ≤30° | 两端读成两个色族，品牌色认不出来 |
| 角色之间（两个独立强调色/填充色） | 会不会分不开、会不会暧昧 | ΔL* ≥10；色相夹角**不落 15–40°**（功能色可登记 waivers 换轴，代价是要写明两轴依据） | 转灰/黑白/色弱时并级；或看起来像「配色没调完」 |

⛔ 把角色区间的 15–40° 拿去判色阶两端是错的：实测黄、蓝两条 ramp 两端本就相差 32–35°，这是旋转补偿做足的结果，不是缺陷。
⛔ 反过来把 20–30° 拿去判两个语义色也是错的：两个色差 22° 合规，但看起来既不像同族也不像对比。

色相夹角越界的修法：推到 ≥60°（明确对比）或压到 ≤10°（同族深浅），调明度解决不了。

**但功能色场景下这条判据不可满足**（2026-11-20 第三轮采样逼出来的）：状态色语义是抢来的——信息蓝、成功绿、警示红／橙，而警示与暖色主色天生只差 20–40°。实测：主色绛红 `#b01e3c`（351.5°）配琥珀警示 35° 是 43.5°（刚出带子就险），把警示压深到 `#b45309`（26°，5.06:1 可读）又落回 38.3°；白底上「≥4.5:1 可读」与「离绛红 ≥45°」二者不可兼得。这不是选色没选好，是结构冲突。

所以 15–40° 这一档留一条**降级路径**，但降级本身要能被证伪：

- 在 palette json 里登记 `waivers`：`{"pair":["accent1","accent2"],"basis":"…"}`；
- 依据须 ≥20 字，且至少盖住**两轴**（面积／形状／位置），只写「面积大」不算——单轴救不了这条带，这正是要登记的原因；
- 登记后这一对降级为 `✓` 放行并在末行报「另有 N 条换轴豁免放行」，⛔ 不是静默消失；
- 登记了却没对上任何暧昧对 ⇒ 反报「失效豁免」，防止改名后旧豁免变成永久免死金牌。

轴从哪来：「面积」是视觉重量（面积×饱和度×明度差），「形状」是图标/纹样冗余，「位置」是不同框/不同屏。三轴里挑得动的写进依据，写不动的就别登记、老实改色相。

**验压回别只看最亮一级的 hex**：超预算时 `emit_tokens.py` 把偏移按同一系数缩小（`k = 30/spread`），比的是**请求色相**，不是 hex 反解出来的色相。最亮一级（L* ≥95）在 8 位 RGB 里色相本身就被量化——`#ffffeb` 与 `#fffeeb` 反解都落在 60°，与请求的 57.6° 差 2.4°。所以「亮端那两级的偏移看起来等距」可能是取整噪声，不是压回不等比；要验等比就看 200–400 级。但**相邻两级反解差 <1° 就不是噪声，是真停级**——那说明封顶把两级压成了同一档，按上一段的整侧比例压修。

### 面积配比（2026-11-22 增）

色相与明度都合规，页面仍可能「有点花」——问题在面积：两个色各占一半，谁也当不了主色。

- **主色约 60%、辅色约 30%、点缀 ≤10%**。两个颜色接近 1:1 就是抢主色，判不过；修法是改面积或拉大明度差，⛔ 换色相。
- 点缀色全页只一处（与 [排版与收尾](type-and-polish.md)「收尾九条」第 1 条同源，这里给判法）。
- 判法要落到数：截图上按色簇统计面积，或按区块估——正文底、卡片底、按钮这三块加起来算主色，点缀只算强调元素。⛔「看起来有点花」不算结论。
- 这条只管比例，不管选色；选色归上面两道门。照片与满屏图形不受 60-30-10 约束，别拿它去判一张产品图。
