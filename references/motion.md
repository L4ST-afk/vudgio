## 三处必做动效

不动的界面像一张静态图：按下没回应、切换没来路；用户只能猜。新页面，或改过操作流程的页面，先把这三处补上：

1. **主操作的反馈。** 按下立刻有反应，完成时交出结果——按钮压下去再弹起、对勾描出来、数字滚到新值。
2. **一处状态切换的来源。** 选中、展开、换视图、增删条目，都要看得见来源与去向，见下文「页面与视图的过渡」。
3. **首次进入时的一次出场。** 主角先出场，其余按阅读顺序跟进，仅在首次进入播放。

这三处之外每加一个；都要能说出它承担反馈、引导、连续、品牌表达里的哪一项。滚动淡入、视差、鼠标跟随、装饰性循环最容易变成噪音。

| 要做的变化 | 优先手段 |
| --- | --- |
| 按下、聚焦、展开这类普通状态 | 浏览器原生过渡；或组件自带的小过渡 |
| 视图切换、元素换位置 | 共享元素过渡；见「页面与视图的过渡」 |
| 拖拽、手势、尺寸与位置变化、多元素协同 | 项目里现成的成熟动效库 等 |
| 品牌画面、材质、复杂物理 | 图片／3D／着色器／预渲染视频；按需取舍；实时 3D 的取舍见 [素材](media.md) |
| 鼠标、触控或滚动驱动的叙事 | 进度直接跟输入走；回滚与快操都要接得住，见 [滚动叙事](scroll-narrative.md) |

要精确控制状态的界面用代码写动画；画面早已定死的可以用生成的视频。实时数据、要人真去操作的控件，⛔ 不能用视频顶替。

## 动手前的四问

按顺序问，前一问答完才问下一问。⛔ 不能先挑曲线再补理由。

1. **该不该动**：用户一天做几次？几十次的别动（键入、切标签、滚动）；状态直接到位；几次的给最短反馈（80–160ms）；首次进入、完成、庆祝这类罕有时刻才配得上长演出。
2. **为什么动**：说得清它属于反馈、引导、连续、品牌表达哪一项；说不清就不做；
3. **用什么曲线**：进场减速、退场加速、来回切换用 in-out；弹簧只留给有物理预期的地方（拖拽、越界、落位）；
4. **多久**：查「时长与幅度表」。界面元素一律 <300ms；整页转场是例外。

三条缓动当令牌用，⛔ 不能拿没有方向感的 `ease` 当万能钥匙：

```css
/* 入场 */
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
/* 双向 */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
/* 抽屉面板 */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
```

Tailwind 项目里这三条由 `theme.css` 的 `@theme` 一并给出（`--ease-*` 命名空间），组件只写 `ease-out` 这类工具类；令牌摆在眼前却还各写各的，跑 `python3 scripts/motion_audit.py --root <项目>` 揪出来。令牌口径见 [令牌](tokens.md)「动效令牌」。

## 手感：用实物定参数

手感从方向的材质与调性推出。命名与选参数（弹簧刚度／阻尼）都用「动作＋实物」。

| 动作 | 实物 | 刚度／阻尼 | 用在哪 等 |
| --- | --- | --- | --- |
| 咔嗒 | 磁铁吸合、卡扣、拨杆 | 350–400 / 10–15 | 按钮、开关、下拉 等 |
| 滑入 | 气压闭门器、抽屉阻尼 | 250–300 / 20–25 | 底部面板、抽屉、折叠 等 |
| 流淌 | 倒蜂蜜、雾散 | 150–200 / 30–40 | 页面转场、主视觉出场 等 |
| 砸落 | 锤击、重物落桌 | 400–500 / 5–10 | 确认、完成反馈 等 |
| 回弹 | 橡皮球、蹦床 | 300 / 8 | 庆祝、儿童与游戏 等 |
| 漂浮 | 氦气球、飞絮 | 100 / 25 | 冥想、梦境、空闲循环 等 |

重材质（石、金属、陶）偏咔嗒与砸落；轻材质（纸、布、雾）偏漂浮与流淌。高频操作配短促动作；少见的品牌时刻才用绵长的。喧闹粗粝的方向可以用硬切、80–150ms 线性跳变、抽帧——那是品牌表达；被禁的只是没想过的默认缓动。

过冲幅度看面积：整页、面板这类大块；过冲 ≤1–2%，再大会晃；徽章、勾选这类小块可以 10–20%，才有弹性。表里阻尼偏低的参数只喂小物件。

把弹簧落成曲线别手算；跑命令：

```bash
python3 scripts/spring_to_linear.py --target 200 --overshoot 8  # 200ms 落定，过冲 8%
python3 scripts/spring_to_linear.py --preset 咔嗒               # 复现上面表里的材质手感
```

它按「位移收进终点 0.5% 以内」定时长；取 20–30 点写进 `linear()`，并附一条 `cubic-bezier` 退路。
⚠️ 上表那组 k/c 是**材质倾向**，不是时长：咔嗒档积分落定约 0.93s，已越过「界面元素 <300ms」。按表选材质，再用 `--target` 反解实际要用的 k/c，⛔ 不能把两者当一回事。

## 串联：前后动作要接得上

一个动作引起的变化沿同一条路径传下去，上段终点就是下段起点。⛔ 不能按钮、面板、数字各动各的。

- **从被操作处出发。** 点「加入购物袋」，商品缩成一点飞进袋子，袋上的数字跟着跳一下；删掉一行，它沿删除按钮方向收走，下面几行补上来。
- **一次切换只朝一个方向。** 卡片左滑时，标题、序号、底色一起左移；数字上滚，进度条也上走。方向一乱，就成了几段互不相干的动画。
- **主角先动，其余被带。** 受影响的元素晚 40–80ms 跟上，幅度更小，像被主角牵过去的；全体同时同幅起跑，看起来只像一起闪了一下。
- **形状接力。** 上一状态的元素变成下一状态的元素：按钮展开成面板、搜索图标拉长成输入框、播放键变成暂停键，一眼看出是同一个东西。
- **动法与画面同材质。** 轻重、停顿、回弹从方向卡的生成引擎和控件语法推出。

### 巧思从产品里找

巧思是让一处动效讲这个产品自己的事，不是多加花样。写成一句话：这个东西的哪一样，因为用户的哪个动作，发生了只有它才会有的变化。

找不到就把三处基本动效做准，⛔ 不许硬造。一页最多一两处巧思，其余保持安静、短促。

## 页面与视图的过渡

**连续。** 用户点的东西就是下一屏的主角。从列表进详情，被点的那项放大成详情、其余淡出；返回时它缩回原位，页面回到原来的滚动位置。原位已不在视口内，先滚到可见再缩回。

**方向一致。** 下一项从右边进入、上一项从左边进入；开与关互为逆过程；侧面板从自己那一侧进出。方向随意的动画比没有动画更容易让人迷惑。

**只变形状时不交叉淡化。** 换视口、筛选、展开说明、缩放——内容不变，只是尺寸与位置变了。让外框直接变形，内容立即显示新状态；交叉淡化会把两张缩放不同的新旧画面叠成重影。只有内容本身换了，才淡入淡出。

**离开、加入、留下分开处理。** 移除的淡出、新来的淡入、留下的移到新位置。三者共用一种淡化，整张列表就会闪。

**选中指示用一块会走的滑块。** 分段控件、标签页、列表当前项，都用同一块底板滑到新位置，⛔ 不许旧的熄灭、新的点亮。选项宽度不同，宽度随之过渡。首次显示、窗口缩放、字体加载完成时直接到位，⛔ 不许从 0 宽度长出来。

**先备好目的地。** 图片、内嵌页等要加载的内容先加载或预渲染，否则动画会停在一块白屏上。来回切换的视图预先渲染并留在页面里，切换时只移动、不重载；加载完成后再淡入，⛔ 不许先闪一下白底。

**离开比进入快。** 退出时长约为进入的 60–70%，用加速曲线；进入用减速曲线或弹簧曲线。

**到头要有反馈。** 已在首项或末项时轻顶一下（往返 10–15px），⛔ 不能毫无反应。

### 整页转场：按稳不稳分三类；

旧页要卸载、新页要挂载；和组件过渡不是一回事。

- **遮罩式（Curtain／Wipe）。** 一块纯色、纹理或几何形划过去盖住屏幕，趁挡住完成换页。最简单最稳，两页结构互不相干，多数页面适用。
- **交叠式（Overlapping）。** 新旧同屏，错开、推挤或分层淡化。看着连贯，但两页 DOM 必须同时存在，层级和内存都要管。
- **共享元素式（Shared Element）。** 一个关键元素从旧页变形到新页，例如缩略图放大成详情主图。最顺也最易坏：快速双击、中途打断、后退、视口变化都会错位闪烁，必须预留退路——出问题就直接呈现到位状态。

首进站的加载屏可以在等大文件时放一小段叙事或进度；站内跳转按「时长与幅度表」的整页取值，⛔ 不能让转场挡着用户看内容。

### 接点要有人过界

把「上一屏怎么变成下一屏」当成要设计的东西，而不是两段各自进出。

- **每个接点必须有承载体。** 相邻两屏之间，至少一个元素存活下来、看得见地变成下一拍：按钮展开成面板、卡片长成页面、标题缩成页码、一块底板滑成下一页的分区。旧页整体淡出、新页整体淡入，只是替换，判不过。
- **静止让动作落地。** 一段连续运动之后要留一段不动（起步 100–200ms，按节奏定），否则画面全程都在动，用户抓不住任何一拍的落点。（本机口径，非实测最优值）
- **镜头只有一台。** 连续叙事里跟主体走、提前一拍把视线预甩到落点；撞击处轻抖一下，随后彻底静止。⛔ 每屏各给一个机位。
- 前两条是硬判据，任何有转场的页面都适用；第三条只给产品片与滚动叙事，普通页面不强求。

## 常驻栏随滚动收放

顶栏压住正在读的那一行，是阅读型页面（长文、文档、演示页）最常见的浪费。让它在读的时候收上去、要翻回去的时候放回来；⛔ 工具型工作台的主壳不做这件事——那里的工具条要随叫随到，收起来等于藏了操作。

- **只让位不消失。** 往下读：整条栏 `transform: translateY(-100%)` 收上去，宽度与层级都不动；往上滑一点就放回。⛔ 改 `top`／`height`／`margin` 去做这件事——那是在动布局，每帧都在重排。
- **页顶常显。** 滚动位置在页面顶部（约两条栏高之内），或刚进页时，栏必须完整可见；⛔ 一打开页面导航就没了。
- **换向按累计位移判，不按单个事件。** 位移不到 6px 不算换向：手指抖一下、触控板微颤都不该让栏跳上跳下。滚到页底那一下回弹⛔ 当成「往上滑」把栏弹出来。
- **约 300ms，可被打断。** 连续换向时从当前位置续走，⛔ 回起点重播。
- **减少动态效果时不位移。** 改淡出淡入，或干脆常显，正文照常可读。

验收：慢速下滚，栏收上去、那一行不再被压；上滑一小段，栏放回；滚回页顶，栏必在；滚到底回弹，栏不跳出来；开「减少动态效果」，不复现位移且内容完整。

## 时长与幅度表

| 对象 | 时长 | 要点 |
| --- | --- | --- |
| 按下、开关、选中指示 | 100–180ms | 按下缩放到 0.96–0.98，约 80ms 内立即生效，松开弹回 |
| 提示、气泡、下拉 | 125–250ms | tooltip 首次延迟约 300ms，二次进入立即显示；从触发点方向展开，缩放从 0.96 起，⛔ 不能从 0 起 |
| 面板、抽屉、侧栏 | 200–500ms | 按移动距离取值，距离越远时长越长 |
| 整页或视图切换 | 350–500ms | 超过 500ms 等于让人等待 |
| 首次进入依次出现 | 每项 40–80ms | 总长 ≤600ms；只在首次进入播放，重渲染与恢复状态⛔ 不能重播 |

界面元素一律小于 300ms；表里超过 300ms 的只有面板、整页这类大块位移。这张表只管界面操作；游戏与抽奖的演出时长见 [游玩](play.md)。

提示的「热度」按组共享：同一排图标、同一段文字里的几处注释算一组，组内第一枚等约 300ms，其余随即打开；指针离开这一组就整组重置。⛔ 每枚各自计时——第二枚又要再等一次，同一屏里就会出现几处迟迟不出的提示。

悬停上浮 2–4px，阴影随之加深；位移超过 20px 的悬停显得轻浮。

## 没有可见结果时给出说明

点击产生看不见的副作用（复制到剪贴板、后台保存、发送），用一条短提示说出结果本身，例如「已复制：……」，⛔ 不能只说「成功」。选中、完成这类确认时刻可以小幅弹出，只在状态首次变化时播一次，重复点⛔ 不能重播。

## 可打断与性能

项目现成的节奏与组件能力先沿用。高频操作反馈要即时，⛔ 不能让动画拖慢事情本身。

动画要能被打断：连续快操作时，新动画从当前位置续走，⛔ 不能跳回起点重播。CSS 过渡从当前值重新出发，适合高频切换；关键帧从头播，适合一次性出场。业务状态立即更新，⛔ 不能等动画结束。

网页上连续动画优先只动变换与透明度，过渡里只写会变的那几个属性；很小的指示块可以直接过渡宽高。每帧都跑的代码要有停下与清理的条件，⛔ 不能一会儿读布局、一会儿写布局地来回切；滚出屏幕或无事可做就停。整页过渡期间页面通常点不动，所以必须短。

性能红线：

- **长任务：** 一次占住主线程超过 50ms 已构成可感的卡顿。把活儿切小、分帧，或搬进 worker；⛔ 一次同步处理整批数据后再说「优化过了」。（阈值 50ms）
- **流水线：** 改 `width`／`height`／`top`／`left` 会走「样式→布局→绘制→合成」，布局最贵而且连锁重排；只改 `transform`／`opacity` 停在合成。判断依据用 DevTools 里紫色（布局）与绿色（绘制）标记实测，⛔ 凭感觉汇报帧率。
- 动画中⛔ 不能改会被大量元素继承的 CSS 变量——一个变量变，所有引用它的元素一起重算。要变就改在根节点，或直接写具体值。
- `font`、`margin`、`background` 这类简写会连带重算整组，⛔ 不能放进过渡。
- 能用 CSS 过渡或 Web Animations API，就别用 JS 逐帧；逐帧只留给必须实时计算的场景。
- 模糊掩膜很贵：只在静态背景上用，⛔ 不能与位移动画同时跑。

有明显位移、缩放或滚动特效处，要照顾开了「减少动态效果」的用户：状态直接到位，内容一样不少。必要信息与主操作⛔ 不能等自动播放、声音或动画播完才出现。

## 验收动作

正常速度操作一遍，再反向操作一遍、快速连按几次：无重影跳动，元素不突然出现、不从奇怪位置飞来、不卡在中间态。开「减少动态效果」后内容直接可读。帧率或性能改善只在实测后才报告。

## 落到网页时的几个坑

- 原生视图过渡适合「同一对象从一处到另一处」：前后两态里代表同一对象的元素给同一个过渡名，同一时刻过渡名必须唯一。
- 过渡只改形状时，把旧快照藏起来、让新状态直接露出来，重影就不会出现。
- 过渡伪元素后面只能接少数伪类（如 `:only-child`）；写 `:not(...)` 会让整条规则失效。要按场景拆规则，就在根元素加属性来切换。
- 内嵌页与图片在过渡里会被截成快照；目的地没加载完就开始过渡，会以空白页收场。
