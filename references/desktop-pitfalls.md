## 一、起点说明

本指南汇总自桌面端生产环境高频返工与踩坑复盘，聚焦阴影裁切、输入法异常、窗口交互与系统级渲染边界，提炼出可落地的排查与防御规约。（自研）

## 二、阴影与祖先裁切：先找真实裁切边约束

### 典型症状约束

卡片投影只露半边、hover 动效触发后投影边缘出现突兀切线、透明/无边框窗口四周出现硬性截断，或圆角容器内的内容在某一帧突然变成直角。（自研）

### 根因与物理机制约束

- 无论将内部元素的 `z-index` 设为多高，只要它的任意祖先节点设置了 `overflow: hidden`（或 `auto`/`scroll`）、`clip-path`、`contain: paint`，或者受限于透明窗口的物理边界，超出祖先容器矩形的像素就会被硬性裁剪。
- 阴影外扩物理公式：
  - 投影外扩量（Spread Distance）：右侧最大外扩约 `offsetX + blur + spread`，左侧约 `-offsetX + blur + spread`。
  - 顶部与底部同理；多层叠加阴影取各侧的最大外扩值。
  - 安全距离铁律：元素边缘到裁切祖先内壁的距离，必须严格大于等于该侧的阴影外扩量！（自研）

### 标准解法约束

1. 内外分层原则：负责圆角裁切的容器放在内层，负责投射阴影与光效的容器放在外层。
2. 滚动轨道预留缓冲：在可滚动的容器内壁，按投影方向预留充足的 `padding`（余量 ≥ offset + blur + spread），避免阴影贴边被截。
3. 透明图像有效像素检查：对透明图片先核对真实有色像素边界，再设定内边距。
4. 透明窗口与系统物理尺寸：无边框透明窗口（如 Electron 的 `transparent: true` 或 Tauri 对应窗口），必须将窗口物理尺寸与 CSS 外层留白同步放大，单改 CSS padding 而窗口物理尺寸不足依然会被桌面操作系统视口裁切。
5. 动态状态复查：在 hover、展开、弹层激活等所有动效落点状态下，均需重新执行自动化审计（见 [验收清单](acceptance.md)）。（自研）

> ⚠️ 边界：严禁无脑将所有 `overflow: hidden` 全局改成 `visible`！`overflow: hidden` 往往承担着防止布局撑破、隔离上下文或维持圆角的职责，应精确定位并只修复真正冲突的那两层结构。

## 三、动效中间帧与圆角遮罩的隐形缺陷约束

### 文字升起过渡中的硬底线约束

- 症状：在文字向上位移动画执行中途，下部遮罩边缘露出明显的水平硬线，而在静态终态时肉眼或自动化矩形检查完全正常。
- 解法：采用与位移曲线同步的 渐变遮罩（Gradient Mask）代替生硬的矩形裁切，让遮罩边缘具有柔和的羽化过渡，消除中途暴露的硬切边。（自研）

### `clip-path` 圆角陷阱约束

- 机制：CSS `clip-path: inset(...)` 默认是直角矩形，不继承 宿主元素的 `border-radius`。
- 解法：需要保留圆角时，必须显式书写 `round` 参数（如 `clip-path: inset(0 round 12px)`），并确保四角曲率与宿主完全吻合。单纯依赖 DOM 矩形检测无法证明曲线像素正确。（自研）

### 粘性定位（Sticky）滚动跳帧约束

- 排查：在复杂弹性布局中，高频 DOM 采样可能显示正常，但在物理屏幕上用户滚轮滚动时能看到跳帧。
- 解法：使用平台原生的 Sticky 约束，并以真实滚轮在合成器绘制帧下进行平滑度检验。（自研）

## 四、桌面窗口外壳、系统托盘与图标规范约束

### 现代桌面窗口结构约束

- 标题栏区域高度约 40px~46px 作为设计基准，遵循平台原生窗口规范。
- 窗口阴影与圆角交给操作系统现代桌面窗口管理器（如 Windows 11 DWM 或 macOS Quartz），避免自绘双重装饰框导致冗余与错位。
- 区分无边框沉浸式窗口的拖拽区域（`-webkit-app-region: drag`）与可交互控件区（`no-drag`），拖拽区内严禁放置可点击或可输入组件。（自研）

### 托盘菜单与窗口失焦收起约束

- 优先复用平台现代菜单外观与键盘导航语义。
- 在自绘独立托盘悬浮窗口场景下，必须完整实现：（自研）
  1. 窗口失去焦点（`blur`）时的即时收起；（自研）
  2. 外围透明光晕的渲染余量；（自研）
  3. 点击托盘图标时的状态切换防抖。（自研）

### 图标资产多尺度适配约束

- 现代应用图标设计偏好连续曲率平滑圆角（Squircle），外角透明无直角白边。
- 必须进行多尺度下采样检查（重点测试 16px、24px、32px 任务栏/托盘小尺寸下的视觉识别度，以及 256px、512px、1024px 高清展示）。
- 避免直接缩小复杂插图导致细节糊成一团。（自研）

## 五、原生组件、自适应高度与滚动语义治理约束

### 区分三种“原生”层级约束

1. 操作系统原生控件：系统窗口边框、文件选择器（Native File Dialog）、系统级上下文菜单。
2. 渲染引擎原生行为：鼠标滚轮响应、触控板手势惯性、文本选择范围、焦点导航环与原生滚动条。
3. 组件库封装组件：第三方 UI 库提供的 Modal、Select、ScrollArea、Resizable 分栏。（自研）

严禁将组件库的自定义 DOM 结构混同为操作系统原生组件，反之亦然。（自研）

### 果冻自适应输入框与局部滚动条收敛约束

在自适应增高的 AI 输入框（Composer）中：（自研）

- 自适应增高三层机制：
  1. 内层 `textarea` 使用 `field-sizing: content`（现代浏览器支持），或通过尺寸监听自动跟随输入量扩展；（自研）
  2. 外容器显式设置高度并添加弹性过渡；（自研）
  3. 外容器保持 `overflow: visible`，允许内层在扩展帧短暂探出。（自研）
- 局部隐藏原生灰色滚动条：在达到 `max-height` 上限转为内部滚动时，用户体验上灰色的系统滚动条极度破坏沉浸感；应通过局部样式（`scrollbar-width: none` / `::-webkit-scrollbar { display: none }`）隐藏滚动条外观，同时完整保留滚轮滚动、触摸滚动、文本选取与键盘 PageUp/Down 可访问性；切忌将此局部处理扩大为全局禁用滚动条。

### 弹窗弹出时背景页面跳动与防抖约束

- 根因：弹窗打开时页面 body 被强制注入 `overflow: hidden`，导致原本占位的系统滚动条瞬间消失，整个页面内容向右突跳十几个像素；弹窗关闭时再次反跳。
- 解法：在真正的根滚动容器上配置 `scrollbar-gutter: stable` 保留槽位；或者采用成熟组件库已内置的补偿机制，严禁在全局手写不准确的 `padding-right` 计算代码。（自研）

## 六、焦点管理、中文输入与历史返回定位约束

### 键盘交互与 IME 组合输入约束

- 发送键默认为 `Enter`，换行使用 `Shift + Enter`（或随系统偏好支持 `Ctrl/Cmd + Enter`）。
- 中文拼音等组字期间（`isComposing` 为 true），按下 `Enter` 仅确认候选词，严禁直接触发消息提交（精密解法见 [手册导读](open-claude-manual.md) 中 500ms 时间戳守卫）。（自研）

### 历史返回与精确滚动位置恢复约束

- 从详情页返回列表或对话主视图时，应依靠数据项唯一 ID 或精准记录的 `scrollY` 恢复视口。
- 避免盲目调用 `.focus()` 导致列表卡片被浏览器默认行为暴力顶到视口最上方并留下刺眼的焦点框。（自研）

## 七、严防“修改未生效”的开发盲区约束

1. 核对最终运行入口：在具有编译打包步骤的桌面工程中，源码修改后必须触发重新构建，确保运行的是最新的可执行产物，而不是历史打包快照。
2. 多平台差异隔离：在同一套代码支持 Web 与桌面多端的项目中，Web 端开发服务器的预览结果不能替代 Electron / Tauri 真实系统窗口行为，必须在对应桌面环境下进行终验。（自研）

## 八、界面排版与视觉污染避坑约束（Anti-patterns & Visual Noise）

### 严禁使用“卡片左边缘带颜色的粗线条”（彩条卡片反模式）

- 典型症状：通过 `border-left: 3px solid #color` 或伪元素在卡片左边缘画一条彩色粗线来标记卡片类别或警告状态。
- 危害：破坏了卡片四边的对称性与圆角的完整封闭性，在暗黑模式或紧凑网格中显得粗暴刺眼、极其过时，破坏了界面的整体高级感。
- 现代解法：采用紧凑的圆角微型徽标（Badge）、微弱的状态圆点（Status Dot，如 6px 呼吸灯）、或利用极轻微的背景微色阶（如 `bg-primary/5`）表达状态，保持卡片几何边界纯净统一。（自研）

### 禁用中点 “·” 作为分隔符约束

- 典型症状：在标题、副标题或元数据列表中使用中点 “·” 来切分标签（如 `2026-10 · 成功 · 45ms`）。
- 危害：中点在不同的系统字体（如 PingFang SC、Segoe UI、苹方、微软雅黑）下基线垂直居中算法严重不一致，经常出现忽上忽下或间距失控的视觉碎裂。
- 现代解法：彻底移除中点，改用 CSS `display: flex; gap: 8px;` 布局留白，或插入高度约 8px~10px 的 0.5px 浅灰色垂直分隔线。（自研）

### 嵌套容器圆角内外不平行约束

- 危害：外层容器设置了圆角（如 16px），内部直接嵌套的列表项或按钮也写死 16px，由于内边距（Padding）挤压，四角出现视觉上的不平行与凹陷感。
- 解法：严格执行同心圆圆角公式：`R_inner = max(0, R_outer - padding)`。当 `padding >= R_outer` 时内层果断使用直角（`0px`）或至多 `2px` 微圆角。

### 冗余说明文案滥用（把 UI 搞脏）约束

- 典型症状：每个卡片标题下都要硬塞一段解释性副标题或占位 slogan，表单输入框每个都配一段使用说明。
- 危害：不仅弄脏界面、稀释信息密度，还会极大地分散用户的注意力。
- 解法：无情删掉所有占位性说明文本。让布局、排版层级、间距与控件标签本身来完成自我说明（Let the layout do the explaining）。（自研）

### 字号失控（>4 种）与小于 12px 的显示灾难约束

- 危害：一个页面出现 5~7 种不同字号导致视觉焦点无序跳跃；使用 10px 或 11px 文字在 Windows 100% 缩放或普通 1080p 屏幕上字体笔画丢失、模糊发虚。
- 解法：全界面字号严格收敛至 3~4 种，最小可用字号守住 12px 硬门禁；依靠字重、颜色灰阶与间距建立层次。（自研）

| 现代解法徽标/圆点/微色阶 | 检查是否采用 Badge、Status Dot 或 bg-primary/5 | 已采用 |
| 中点分隔符禁令 | 检查界面文案与标签是否使用中点 “·” | 严禁使用 |
| flex gap 分隔 | 检查是否改用 display: flex; gap: 8px 或 0.5px 浅灰色垂直分隔线 | 已改用 |
| 同心圆公式 | 检查是否执行 R_inner = max(0, R_outer - padding) | 已执行 |
| padding >= R_outer 直角 | 检查内层是否使用直角或至多 2px 微圆角 | 已使用 |
| 冗余说明文案禁令 | 检查是否存在占位性说明文本 | 无情删掉 |
| Let the layout do the explaining | 检查界面是否依赖布局本身自我说明 | 已依赖 |
| 字号阶梯数量 | 检查全界面字号是否收敛至 3~4 种 | 3~4 种 |
| 最小字号 12px 门禁 | 检查是否存在小于 12px 的文字 | 守住 12px 硬门禁 |

三态结论：每条判据分为「过 / 不过 / 证据不足」。缺画面或缺材料一律记为「证据不足」，不得直接判「过」。
