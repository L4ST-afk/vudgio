# 只读取证

> 归属：约束满足闭环 · 第 5 步「判据验收」· 只读取证员。
> 用户只要评审时走本流程：只交证据、诊断与建议，⛔ 改产品文件，⛔ 生成新方向，⛔ 进制作后的修正循环。结论三态：过／不过／证据不足。

1. 先写四项：评审对象、用户目标、设备、已知约束。只读相关页面、截图与材料，⛔ 通读整个项目。比较已有方案时让它们保持现有内容与范围，⛔ 先替任何一方补齐成自己的设计。
2. 能运行或能看图时取真实证据；不能就把限制写清，⛔ 把推测写成实际视觉或交互结论。按 [视觉判据派发](visual-review.md) 选适合「现有界面」或「候选方案」的评审方式；评审标准由评审者自己读，主 Agent 只交接材料。
3. 有隔离、能看图的执行者时，派一个没有制作历史的评审者；没有就主 Agent 自检并写明「未独立评审」。要验主要流程时按 [操作走查派发](ux-review.md) 取走查证据；纯视觉评审⛔ 额外走查。
4. 报告按影响排序，每条写位置、观察、依据、建议。比较方案时分别说明适配与代价再给选择建议。每条建议都必须挂一条可机判的达成判据：满足写「过」、不满足写「不过」、缺画面或缺材料写「证据不足」。交完报告即停，⛔ 修正、⛔ 实现建议、⛔ 顺手扩任务范围。
