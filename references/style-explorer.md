# 候选对比页（外壳）

> 归属：约束满足闭环 · 第 2–5 步「构建候选解与逐条验判据」的外壳。
> 把几个候选并排放进同一页；由用户来挑。外壳只负责比较与挑选，本身不带风格倾向，也不充当候选的参考。

候选之间只改构图、信息怎么组织、字体的气质、色彩关系、疏密与用图方式；核心内容、主要动作、目标用户保持一致。放几个看用户要几个、真正有差别的有几个，⛔ 不能复制整个产品来凑数。

## 输入怎么给

一轮只出一个对比页。能跑起来的就用真实页面：自写的 HTML 小样直接内联；项目里的方案用本机地址，跑不起来才退回截图。每个方案一张画面——存量项目选入口或差别最大的那一步，整站方案只放代表页。

传一个候选目录；或直接传几个 HTML 文件。显示名取 `<title>`，没有标题就取文件名。同目录有 `manifest.json` 会读它补方向信息；没有 manifest 也能生成。

最小可用的写法：

```json
{"candidates": [{"source": "a.html"}, {"source": "b.html"}]}；
```

| 情况 | 要加的字段 |
| --- | --- |
| 固定画布的界面 | 顶层还是候选里写 `"nativeViewport": "宽x高"` |
| 自写的可操作小样 | 候选加 `"interactive": true` 等 |
| 要起服务才看得到的页面 | 候选加 `"kind": "url"` 与本机 `url`；顶层可给 `serve` 启动说明 等 |
| 改已有页面 | 把现状也放进来；标 `"baseline": true` |
| 只有截图 | 候选加 `"kind": "image"`；`source` 指截图 |

HTML 与图片候选只填 `source`；本机地址候选按上表填 `url`。候选来自方向卡时；再补 `name`、`concept`（北极星那句）、`typography`、`palette`（色值数组）、`traits`，对比页会把它们和画面一起摆出来供挑选；省略的项不显示。其余字段见生成器 `--help`。

## 生成与打开

```text
python3 <skill>/scripts/build_explorer.py "<候选目录>"；
```

也可以传多个 HTML，或直接传 `manifest.json`。没有 `python3` 时换 `python` 或 `py -3`。产物默认生成在输入旁边，名为 `style-explorer.html`；改过候选要加 `--force` 重生成，否则打开的还是旧画面。生成器会把需要改的地方一次列全。真跑不了生成器时，把候选原样交给用户并说明对比页尚未组装，⛔ 不能临时另造一套工具。

有本机地址候选时；交付阶段让开发服务器开着。用户后来说「打开对比页」：读 manifest 里的 `serve`，在 `cwd` 后台跑 `command`，等 `url` 能访问再打开。

## 选完之后

用户点「选择」会复制一句话；例如「<轮次>：选 03 <方向名>」。用户粘贴它或直接说出选择后，按轮次与编号对照当前 manifest，确认属于这一轮，再把选择与备注更新进设计说明，然后回到产出这个对比页的流程接着做。对比页不写回任何文件，也不会自己给 Agent 发消息。

## 交付前核对

对候选目录跑一次 `node <skill>/scripts/take_shots.mjs <manifest 所在目录> --size desktop --thumb --out shots/explore`（一次出齐各候选缩略图与并排总览 `sheet.png`），逐张核对：画面、状态、视口与 manifest 写的一致，中文字体真的渲染出来了。判断字号与细节要用单张查看的「实际尺寸 100%」，适应窗口的缩小图⛔ 不能算可读性通过。对比页本身的功能由 Skill 自带测试保证；任务里不验证、也不读模板源码。
