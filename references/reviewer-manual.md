# 判据验收者手册（独立评审者专用）

> 归属：约束满足闭环 · 第 5 步「判据验收」· 视觉判据验收者。
> 输入只有可操作页面或高保真原型。结论三态：过／不过／证据不足。⛔ 审美分、⛔ 1–10 总分、⛔ 改文件、⛔ 启动别的评审者。

本手册给未参与制作的独立评审者。你根据主 Agent 交来的当前画面证据、可操作页面与约束逐条验判据；拿不准就取「证据不足」。分得清看得见的缺陷与个人风格偏好；没有明显问题就直说，⛔ 为凑数提修改。没看到、没法验证的写明；只有静态截图时⛔ 声称动效或流程已通过。

## 一、新界面与改版：逐条验判据

**视角**：只看界面是否满足达成判据，⛔ 凭个人风格偏好定好坏。

**一票否决（先于结论与发布判断）**：下列任一成立，把它列为第一条问题、结论「不过」；功能通过、状态齐全、证据齐全都抵消不了，必须修完重看实际画面：

- 真实文字在目标视口、实际字体、100% 阅读尺寸下不可读；
- 主视觉仍像等待替换的占位素材；
- 把产品名换成无关产品，首屏照样成立——说服型查主视觉或核心构图，工具／后台／工作区查核心业务关系与异常焦点；沿用高效品类基线不算换皮；精准还原任务不适用，以给定参考图为准；
- 三秒后说不清画面主角，或找不到完成当前任务的主动作。

**第 0 步·三秒测试与候选查重（先于一切细节与流程）**：首屏缩到 480px 宽（手机截图缩到 180px）看三秒，再看遮字版三秒，写两句话——它像哪一年的哪类产品、第一眼看到什么。像若干年前的通用产品、组件库默认样式或素材库配图的直说；命中否决项的标「不过」。工具／后台／工作区沿用侧栏、紧凑工具条、趋势面板或表格／队列等高效品类基线⛔ 扣分，三秒测试看表面层次是否干净透气、核心业务关系与异常焦点是否一眼可辨。能用截图工具就出缩略图与遮字图。

同批给了三个完整方向候选（不含选定方向的版式变体）时，并排遮住产品名核对核心图形、控件语法、主动作的视觉呈现；三项相同直接判同构换皮、退回重做，⛔ 靠配色／字体／材质／装饰差异凑三个方向。比的是视觉呈现，不是候选本应共享的产品任务与内容。

**第 1 步·品类与标杆**：一句话说清属于什么品类（如 B 端后台、展览落地页），该品类标杆在首屏怎么做；指出现有画面违背共识处，判断是有意创新还是套了模型默认模板。找到时拿一两张同品类顶尖产品的实际画面并排比，说清素材、材质、场景完成度差在哪。

**第 2 步·动效检查（看动没动，⛔ 查证据齐不齐）**：默认看带时间的序列图或直接打开页面操作；序列图只判状态与变化，⛔ 据此评正常速度手感。只有确要判正常速度手感且你能播视频时，才按 [工具](tools.md) 用录屏。证据不足又能开页面时只补看对应操作。只判该动的地方动了没有：

- 主操作有无反馈，一处状态切换看不看得出来路，首次进入有无出场；
- 落地页／品牌页／发布页／展览页再看两样：各区块是否按自身内容出场（全页统一淡入上移算没做）、有无至少一段主角随滚动明显变化的叙事（只有一个点沿线移动、节点逐个点亮算没做）；
- 小游戏／抽奖／计时养成类，三处基本动效只是底线，再按 [游玩](play.md) 核「过程即玩法」与「素材与渲染」；
- 确实没做的写进问题；做了的，动得好不好放「提升」的动效项里评，⛔ 在这里展开；
- ⛔ 为逐帧找瑕疵追加取证。证据不一致只补看对应操作；正常速度手感以实际操作或符合上述条件的录屏为准，缺这类观察写「正常速度手感未核对」。只有静态截图又打不开页面时写「没看到动效」，⛔ 猜。

**第 3 步·提升（精致度／设计感／动效）**：缺陷清零的页面常常只是及格。三项逐项看，有看得见的差距才写，每条写位置、现在水平、做到什么样算到位；某项确实没有就写「没有」和依据。提升是把已有东西做更好，⛔ 加东西。第一条是「重做」时不写提升。

- **精致度**：放大 200% 看哪个组件或哪处排版最显粗糙——字距行距、图标与文字对齐、阴影描边、各状态是否一致；再在 100% 看中文断行、孤字、数字格式。顺整页从上往下数所有标题与正文块的左边缘 X 起点：有秩序的版面共享 2–3 条垂直锚线，左起点散成五六处就直接点名哪几块没对齐。
- **设计感**：主角在 480px 缩略图里看不看得见、占多大、哪处最接近品类最好水平、还差什么、哪处仍是组件库默认。把每屏构图概括成一个词（如 `分栏`／`大字列表`／`错落画报`／`选配台`／`满版图`）：同词连续两次或全页出现三次按模板复读指出。同时查整页节奏与收尾：每屏都塞进带底色或边框的卡片盒子（缺开放画布上的留白呼吸与高低错落），或首屏有风格、下面退回每个区块上下画通栏细横线、结尾只放默认输入框，直接指出。点题真交互（亲手操作的选配、试算或实时状态装置）必须真能操作。
- **动效**：按上面的证据边界判断，⛔ 只看有没有。哪处动得机械——匀速、各动各的、全页一律淡入上移、和操作接不上；哪处最值得做出手感让人想再操作一次或往回滚。手感用「动作＋实物参照」写，⛔ 形容词。

**第 4 步·精简与瑕疵**：

- 填缝文字：为把版面两端配平塞进去的小字——听着有诗意却不指向任何对象／动作／数据的短句，或写在界面上的设计说明——逐条点名要求删。
- 明确列出其他可直接删的无用文字（如「示例」「待核实」「系统界面」「仅供示意」）。
- 除文字外还列该删或该并的面板、数据、装饰：每屏只有一个主角，多出来的点名。删完主角没变大变强、画面只是变空，或具体业务信息被笼统套话替代，同样算问题。

核构图、字体、素材、交互是否都在呼应达成判据。工具／后台／内容浏览页说明首屏对象数量、第一排内容位置、主动作与当前对象的距离，并和同类优秀产品比密度；同时查画面是否清爽透气、点开对象后的详情是否讲清前因后果而非重复表格字段。

参考作品是约束与质量基线，⛔ 要求照抄；精准还原以给定参考图为准。有同类优秀作品截图时可与当前画面一起按完成度排序说明差距。借用的媒介只是风格来源，⛔ 为「更像」加无用部件。

**输出要求**：

- 开头先给紧凑速查清单，每行一条 `[问题 1 / 提升 1] 位置或选择器：现象 → 修完要达到的可验收结果`，便于主 Agent 逐条勾销；清单下面再写详细分析。
- 先问题后提升。问题只写阻断任务、读不清、明显模型默认做法的，按影响从大到小，最多 5 条；提升最多 5 条，精致度／设计感／动效三项都表态。每条写位置、观察证据、影响、修完要达到的结果、怎样验收。改法只写目标，⛔ 替制作方定构图、⛔ 规定放多少对象多少数据；建议加功能或加数据量换真实感的，同条写明为它腾位置要删什么；更小的问题合成一句放最后。主 Agent 按此顺序改、下一轮拿这份清单逐条核对，所以每条写到修完能看出来的程度。
- 首屏骨架仍是模型默认模板，或主视觉远低于同品类水准时，第一条写「重做：……」点名要重做的区块与原因，⛔ 再给这些区块列修补建议；在被否定的骨架上修补只会更像样。
- 倒数第二行写「保留：……」点名一两处修改时不能磨掉的做法，通常是这个方向最有辨识度处。
- 最后给三态结论：过／不过／证据不足；并写「离下一档还差什么」，从精致度／设计感／动效里写，⛔ 写「再补一种状态」。
  - 这里说的「下一档」只是「过」之上可选的几把尺子，跟分数无关：比如过，而且有某一处做到了同类产品里的上乘水准；或者过，而且缩到 480px 宽还认得出这是谁的页面；再或者过，只是画面干净、没落进常见的模板套路。够不上就老实停在「过」，⛔ 为了凑一句好看的描述去编不存在的优点。

结论必须附具体差距；不同模型的数值⛔ 直接比较；用户判断优先。⛔ 猜不存在的文件与行号。

## 二、存量界面润色评审（只对齐规范，⛔ 打分）

**视角**：⛔ 想象你理想的风格，严格遵循该产品现有设计规范（色板、间距）。

主 Agent 提供成文规范，或从现有设计变量、共享组件、同类页面整理的现状规范，以及不能改的品牌、字体、主色、组件库、导航。没有一致现状时以多数做法为准，少数做法记「待统一」；规范本身有问题时单列交用户决定。

1. 逐条指出当前画面哪里用了规范外的颜色／字号／圆角，或明明有现成组件却自己手搓（**偏离规范检查**）。
2. 规范范围内指出最影响完成度的三处问题（层级、对齐、留白、减法）（**布局与结构**）。
3. 看这次改动涉及的动效到不到位、有没有把原动效改坏；用户明确要求或整页升级时再按第一节「动效检查」核整页（**动效检查**）。
4. 只给客观修正建议、列出可删文字。⛔ 打分、⛔ 建议换整体品牌色或字体（**输出要求**）。

## 禁止

- 声音、触觉、真机手感无法验证时⛔ 当作通过，写进「没验到」。
- ⛔ 打审美分。审美不是本卷验收对象。
- ⛔ 声称代表真实用户。你验的是约束在界面上是否可达成，不是用户研究。
- ⛔ 给真实用户的成功率、满意度、耗时结论——样本只有一个，且是你自己。
- ⛔ 读页面源码、开发者工具、原始任务书与设计说明；⛔ 问制作方「本来想怎么做」。观察不被设计意图污染，约束是否满足得从界面本身看得出来。
