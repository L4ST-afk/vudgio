## 约束采集：产品事实先写成可判句

先写下本产品的事实：用户、品牌、任务、真实内容与对象、使用场合、设备、已有素材、技术条件和交付限制。设备写明主视口与支持范围；用户没指定时；主视口照着这款产品最主要的使用场景来挑，只定一个。拿不准的信息直接标成未知，不要拿参考产品里的内容搬过来，补成自己的事实。品类也要先认清：一线产品已经为用户建立了怎样的结构、完成度做到了什么份上，用户的期待正是照着这些来的。此后的调性与概念，只能在这块地板之上做偏离，偏离要讲得出产品上的理由。

产品参考与交互参考，两类各自挑选、各自记录，来源可以落在同一家；也可以选择不同产品，但两类证据不能合成一份“干净、好用”的印象。按四步做：

1. **说出品类和产品参考。** 写下品类；再选风格最鲜明的两三家，不一定是最有名的。产品参考回答首屏有什么、内容怎样组织、视觉身份怎样成立。
2. **拿到真实画面；拆产品参考。** 用宿主的浏览器或搜索取首屏和关键内容的真实画面，存进任务目录，对着图拆，不凭记忆写。页面打不开或 404 时换地址再试一次，还不行就换一家；拿到两家的真实画面就够。拆成 6–10 条看得见的要素，每条写“是什么样、为什么这样做”：内容层级、首屏骨架、字体、颜色、图标与素材、文案语气，以及它们服务的使用场合。只有“干净、留白、一种强调色”就是没拆到位，换一家重拆。确实拿不到画面时，在方向卡“产品参考与取舍”写明“未看图，凭记忆”，并把字体、色彩、主视觉三栏标为待验证。
3. **单独拆交互参考。** 选核心动作做得成熟的一家；取从入口到结果的真实画面或录屏，写下“触发 → 对象变化 → 反馈 → 下一状态”，以及任务涉及的关键状态；控件形状与手感只有怎样服务这条路径时才记。产品参考里没有出现的交互，不得凭它的视觉风格推断。拿不到真实证据时，在“交互参考与取舍”标明，并把核心交互标为待验证。
4. **分别决定留什么、换什么。** 拿本产品的受众、内容、任务和使用场合逐条对照：理由同样成立的留下；理由不成立的换掉。产品侧的取舍写进“产品参考与取舍”，操作与状态侧的取舍写进“交互参考与取舍”，不互相代替。

拆的时候分清三样东西：

- **基线**：用户已经期待的结构；例如画廊里作品先行、筛选在顶部，商店里购物车在右上角。沿用它，用户不用重新学。
- **套路**：这个品类人人都在用的默认版式。一轮方向里至少一个要打破它；见“差异检验”。
- **撞脸**：字体、配色、主视觉和图标都和某个标杆一样；只换了名字。任何方向都不允许。

## 主角与主动作：唯一主角、唯一主动作、可见结果

拆完参考之后，先为首屏和每个关键状态各写两句：**唯一主角是什么；唯一主动作是什么.** 重复解释、同权重次要动作和没任务贡献的装饰，先删或降级；对象名称、判断依据、当前状态和主动作不能当多余内容删掉。保留其他动作时，写清怎样降级，再来一条 `主动作 → 主角或对象变化 → 状态反馈`，确认动作有可见结果。

## 判据写成：模糊词必须翻译

“高级、精致、克制、史诗、有文学感、简洁”不能当作设计理由。用户或你自己说出这类词时；先翻译成可观察的决定：

| 模糊词 | 翻译成什么 |
| --- | --- |
| 高级 | 先说清是哪一种高级；再决定字体的对比、分隔的方式、间距的尺度和色相的数量。只说高级什么也没决定 |
| 精致 | 公差：字距怎么调、对齐到几像素的网格、阴影最多几级、色相最多几种 等 |
| 克制 | 饱和度预算；例如强调色不超过画面 10%；动效幅度上限；色相数量上限 |
| 史诗 | 尺度：展示字多大、主图占多少面积、明暗对比多强 等 |
| 文学感 | 字族的性格、行长、行高和配色；各取什么值 |
| 粗糙 | 用哪些手段；各用到什么程度，例如错位多少像素、旋转多少度 |
| 简洁 | 密度档位；以及删掉什么、为什么删。简洁是结果，不是指令 |

翻译不出可观察决定的词；从理由里删掉。

> “高级”可以再拆成三层可指认的形态（从容／秩序／克制）；见 [design-direction-2](design-direction-2.md) 末节。

动效与交互上的模糊词同样必须翻译为具体模式。

| 动效模糊词 | 翻译成什么 |
| --- | --- |
| 滚的时候动起来 | 先分清是滑动触发还是滑动驱动；见 [滚动叙事](scroll-narrative.md) 的“滚动交互的两种模式”；未明确时按单向一次性处理 |
| 切页面丝滑一点 | 选定转场模式：遮罩式、交叠式还是共享元素；取舍和时长见 [动效](motion.md) 的“整页转场的稳定性取舍” |
| 背景有立体感 | **分层视差**：前后景的速度差和哪些层不做视差；按 [滚动叙事](scroll-narrative.md) 的“视差与一镜到底” |
| 首屏要有冲击力 | 明确首屏单一主角（大字排版、一件实物、核心 3D 或视频）；不堆砌次要修饰；进场时长见 [动效](motion.md) 的“时长和幅度” |

## 满足解生成：独立概念与把关

需要主 Agent 起新概念时；下面这套独立概念流程，照着走一遍即可。用户手里若已有完整概念，就不必再从头另起；入口若已指定概念专项，照专项的产出走，不再重复派通用概念子 Agent，不过挑选概念、执行独立把关，仍然落在主 Agent 身上。

### 独立概念生成与把关

1. **主 Agent 只备事实包。** 事实包要写清这几样：产品自身事实，用户与品牌两端的约束，谁是主角、哪个是主动作，哪些交互基线必须保留；以及素材、技术和设备限制。不给主 Agent 已想到的方向或偏好的风格。
2. **全新子 Agent 出概念.** 至少拉一个没接触过本任务的新子 Agent；并行时按不同事实角度拆给几个。只交事实包；不交标杆截图、主 Agent 的构想，也不给其他子 Agent 的结果。凑齐至少三个候选，每个回传：一句概念、核心动作怎样完成、主视觉与关键素材、一个记忆点、资产与技术依赖。至少一个候选要从本产品特有对象或动作长出，不从标杆派生。
3. **主 Agent 选择.** 按任务路由定的对外方向数来选：默认只选一个，明确探索多个时才多选；内部候选至少三个的要求不因此取消。不先内定答案，再让子 Agent 佐证，也不把重复概念换词照收。为选中的概念各配一个生成引擎，写成方向卡，再按“差异检验”先过适配和落地门槛。
4. **另一位全新评审者否决或放行.** 把关的人不能是概念子 Agent；这一步只用事实包、用户约束和被选中的方向卡来审，不看主 Agent 的推荐。每张都要写“通过 / 退回 + 理由”：把受众、品牌和任务适配、核心交互、资产与技术成本、设备约束、六项差异都核一遍；若多个方向只是在一家标杆里换皮，或者有一条陪跑方向，就退回这一组。主 Agent 修完再交同一位评审者复核，全部放行才给用户或做首屏，不放任它自己无视退回意见。这一步只审概念、方向卡和灰度，不排视觉分，也不顶替真画面评审。

宿主不能派子 Agent 时；主 Agent 按同样输入、交付项自己来，设计说明上写“未独立生成概念与把关”；适配和落地门槛照做，不声称独立评审。

### 把概念翻译成生成引擎

每个方向都从一个具体的引擎出发；而不是从形容词出发，不同方向最好用不同的引擎。引擎的内容来自这个产品的证据：受众、内容、使用场合和品牌已有的资产。

- **材质 × 环境**：一种材质放在一个具体的环境里。由它推出光照、深度、边缘的处理与动效的阻尼。
- **一个具体场景**：一个有时间、地点与光线的场景。由场景里的光线、声音、材料和节奏推出质感和动效速度。适合情绪型工具。
- **角色原型**：给产品一个具体的性格；让性格决定字体和动作。
- **一场设计运动或文化语法**：选一个和产品的题材、受众或地域有真实联系的设计运动或视觉传统；借用它的语法，而不是贴它的图案。
- **其他领域的整套表现形式**：把另一个领域的媒介或器物的表达方式借过来。只借它最有辨识度的一两个手法；页面本身仍是原来的体裁；不把那个媒介的部件一件件搬来，那会变成道具堆砌。
- **打破一个具体常规**：改变比例、阅读顺序或操作组织；同时保持可读、可学、功能完整和目标设备可执行；不把刺眼色彩或失控构图当作引擎。

引擎决定结构、手感、质感与动效；颜色按下一节单独定。

## 定色彩

产品自己的品牌资产、实物和内容画面是颜色的第一来源；主视觉就是产品实物时；主色可以直接从实物里取。没有现成主色时，不要直接拿生成引擎里那种材质或场景的固有色当主色——隐喻一落到黄铜、木纹或暗房，不同的产品最后就会撞进同一组颜色。按三步定：

1. 先写两行；几个方向共用：这个品类最顺手的默认配色是什么，写出底色和强调色；拆过的标杆各占了哪个色相和明暗。
2. 每个方向定一套不同的色相和明暗；或明确的黑白，用一句写它来自这个产品的什么：内容、受众或品牌资产。避开刚拆过的标杆配色；至少一个方向跳出这个品类的默认配色。
3. 写出至少三层：底色、主强调色；以及由它们派生的选中底、描边和禁用态。

黑白灰加一种强调色；哪怕彩色一点不用，色彩身份照样完整——这时颜色由内容来承担：产品截图可以，用户的照片、随便一张画也可以。方向之间不拿明暗做划分：头一号的失败就是“一个亮、一个暗、一个暖”这种各凑一摊，每个方向都得有自己的色相家族或材质感，明暗只是最后自然得出的结果。

## 定首屏与工作区骨架

等唯一主角与主动作落定、概念和关键素材的来源也有了着落；先把灰度结构画出来，再照着它做成带视觉细节的首屏。每个方向只画主视口的首屏，用的东西限于灰阶块、必要文字与动作标记；要写明内容怎么分层、对象摆在什么位置、状态怎样反馈、阅读从哪里起步。唯一主角拿最高的视觉权重；唯一主动作贴在它旁边，或跟在它之后，其他动作则降级。要是主动作会改状态，就补前后两张。只有另一端会改布局或输入时，才补那端的灰度；否则留到实现后检查，概念阶段不写两套方案。

灰度一到手就看得出问题——主角、主动作、状态变化分不开，那就回头重新排主次。结构若和别家撞了，先把结构重写，别指望字体、色彩、主视觉能把它救回来。标题之外的文案一律等骨架定下来再写，写的时候迁就骨架，不是反过来。结构照页面要干的活来挑：

- **来听一句话、看一张画、被说服的页面**（落地页、品牌页、产品发布页、展览页）。
  从 8 种首屏骨架里选；跳出左右分栏默认模板。详见 [说服型页面首屏骨架](direction-persuasion.md)。
- **来看内容、挑东西或处理对象的页面**（画廊、商店、信息流、文档、作品集、工具与后台）：
  首屏就是第一排内容本身或工作区。面包屑、标题、实时状态与全局筛选合并为一排紧凑顶栏（约 `56–64px`）；第一排内容要完整出现在首屏；不放首屏口号，也不放解释这个页面是干什么的段落。多模块后台采用紧凑三行布局（首行 4 张指标卡可将进度环内嵌、中行主态势图配动态流、末行主数据表配排行），在 `1440×900` 视口内同时露出核心模块与主表前几行。独立单页优先将 HTML、样式与脚本内聚在单个 `index.html` 中，汇总数字与明细保持直观自洽即可，动手前不另写脚本验算公式；完整详情与日志按需在选中对象后滑出或展开，不用多层小卡片和满屏彩色标签把桌面塞满。
- **两种都有时**（例如商店首页顶上有活动横幅）：以用户最常来做的事为准；横幅可以留，但不能把第一排内容推出首屏。

## 方向卡

各方向一张卡。每项都要能落到具体数或做法，不能只给形容词。想探索并做出几个首屏，就做几个方向；调性、产品参考与取舍、交互参考与取舍共用一张（候选按不同调性归，就让调性各填）。先填北极星、主角与主动作、生成引擎、首屏骨架、字体、色彩、主视觉、图标、控件语法、核心交互、记忆点、资产与技术；其余栏等方向定了、做完整页面之前再补。派生版式时，每个版式变体只重写首屏骨架、页面结构和主视觉三栏：

| 字段 | 要写到的程度 |
| --- | --- |
| 北极星 | 一句能指导取舍的意图：给人的第一感受是什么；整页围绕什么展开 |
| 主角与主动作 | 首屏唯一主角、唯一主动作、动作后的可见结果；其他动作怎样降级 等 |
| 调性（可选） | 本卷不靠定调性起方向，这栏可留空。若确要用一句话说整体感受，须照前面的模糊词翻译落成可观察决定（字族/色相数/间距尺度/动效幅度），⛔ 停在形容词 |
| 产品参考与取舍 | 品类、参考来源与真实画面路径（没看图就写“未看图；凭记忆”）；内容、骨架和视觉身份分别沿用、换掉什么，为什么 |
| 交互参考与取舍 | 核心交互参考与真实画面或录屏路径；按“触发 → 对象变化 → 反馈 → 下一状态”写借鉴什么；关键状态怎样调整，没有真实证据就标明 |
| 生成引擎 | 用了哪一种；具体是什么，来自这个产品的什么证据 |
| 首屏骨架 | 先写用户来首屏看什么。内容页写首屏能看到几个对象、页头占几行；说服型页面写从骨架表里选的哪一种。附主视口灰度线框：每块是什么、占多大面积、阅读从哪里开始；主动作和状态反馈在哪里 |
| 页面结构 | 首屏以下怎么组织；例如单列沉浸滚动，或导航、内容、详情三栏 |
| 各区块的形式 | 首屏以下每个主要区块（产品实样、功能、价格、隐私、结尾等）在这个方向里长成什么东西。形式从生成引擎推出；不是同一个模块换颜色 |
| 字体 | 具体字族、字重和尺度关系：展示、正文、数字各用什么；相差多大 |
| 色彩 | 按“定色彩”写：十六进制色值及用途；至少三层，再加一句它来自这个产品的什么 |
| 主视觉 | 哪张图或哪个图形承担情绪与识别；来自复用、生成还是排版本身 |
| 图标 | 用哪一套、什么描边粗细和端点；或者不用图标、改用字符和编号 |
| 控件语法 | 按钮、输入、选中、标签、状态和动效共用的一套形状和手感；用一句话写清，例如圆角多大、描边多粗、按下时怎样变化 |
| 核心交互 | 用户从什么入口做一个主动作；对象怎样变化、看到什么反馈、进入什么状态；涉及哪些关键状态 |
| 记忆点 | 集中发力的一两处：在哪个时刻或位置；用什么材质、动作或画法，见“让人记住的一刻” |
