# 视觉判据派发协议（主 Agent 专用）

> 归属：约束满足闭环 · 第 5 步「判据验收」的视觉判据派发。
> 评审标准在 [评审手册](reviewer-manual.md)，由评审者读；主 Agent ⛔ 不读它，只按下表交接材料。结论取过／不过／证据不足，⛔ 给 1–10 分。调用方已指定领域标准时连同任务模式一起交接；冲突检查项按领域覆盖，是否打分、是否只读仍由任务决定。

## 一、触发与模式

完成一个关键页面、方案或改动后，按下表选派发方式：

| 改动情形 | 交给子 Agent 的话 |
| --- | --- |
| 新界面，或推翻现状重塑 | `读 references/reviewer-manual.md，按【全新界面与改版评审】逐条验判据，给三态结论（过／不过／证据不足）。` |
| 已有界面上整理、升级、润色、扩展 | `读 references/reviewer-manual.md，按【存量已有界面润色评审】对照现状规范指出偏离点。不打分。` |
| 小改动、单处间距或颜色微调 | ⛔ 不派；主 Agent 自行核对。 |

模板里的路径要换成本 Skill 目录的绝对路径（子 Agent 工作目录不是本目录）。派发话术末尾统一带一句：`先扫一眼代表画面的整体构图、文字读不读得清、主动作找不找得到，再按对应标准逐条验；手头证据够判就不再补截图，也别要求凑齐全语言、全页面、全状态。`

## 二、交接清单

用隔离执行能力时按三类给料：

- **必给**：按 [工具](tools.md) 默认范围选出的当前版本截图、按需的动效证据（注明设备视口）、用户原始任务、设计边界与约束；有方向卡时只摘其中「达成判据」那一句，其余硬性约束（如品牌要求每屏出现字标）也摘成一句，⛔ 交整张方向卡。
- **有则给**：现有项目的色彩规范与组件约束（存量老项目必须给）；方向卡的选色记录（颜色来自产品的什么）；项目有 `DESIGN.md` 同类文件时——存量润色评审整份给出并以其为标准，新界面与改版评审只摘品牌资产与「不要做」进约束。
- **⛔ 不给**：源代码、替自己辩护的说明、此前评审打过的分数。

证据必须属于当前版本且评审者能访问。本轮没改到的状态与动效可沿用上轮证据文件，交接时注明沿用。长页给能看清整体节奏的整页图；文字或关键细节判不了才补局部，⛔ 细节图替代整体构图。

动效不必逐项备证：交已有序列图，或给可直接操作的页面地址；录屏按 [工具](tools.md) 条件取用，⛔ 为每个状态补录。只有现有证据不足以支撑结论时才让它补看对应操作，⛔ 重走已能判断的流程。

无隔离、能看图的执行者时，主 Agent 按同一手册自检，交付写明「未独立评审」；无实际画面时⛔ 给视觉分。

## 三、反馈处置

- **第一条若为「重做」**：回方向卡重定被点名区块的骨架或主视觉，⛔ 逐条打补丁。
- **按清单顺序改**：问题从影响最大往下改；「保留」那行记进设计说明，改时对照，⛔ 把它修平。
- **落成具体调整**：把高层意见（太挤、层级不清）翻成间距、字号、阴影的实际改动。评审者要动用户锁定的品牌色或大框架时，写一句理由后不采纳。
- **防死循环**：双方意见僵持、来回横跳且无可见收益时，保留最佳版本并停止循环。
