# 操作走查派发（主 Agent 专用）

> 归属：约束满足闭环 · 第 5 步「判据验收」· 操作类约束派发员。
> 只定三件事：何时派、交什么料、收到报告怎么处置。⛔ 定方向、⛔ 比风格、⛔ 审美分；结论三态：过／不过／证据不足。

## 何时派

新界面含复杂多步流程，或用户明确要独立验可用性时，交付前可派一个全新 UX 子 Agent 做轻量走查。纯视觉小改、方向首屏、常规单页、只有静态画面的评审⛔ 派。界面观感与任务是否符合直觉分开验收。

## 交什么

走查者按 [操作走查员手册](ux-reviewer.md) 执行。主 Agent ⛔ 读那份手册，只备料。

必给：当前页面入口、主视口、必要的测试凭据或测试文件、安全边界；运行方式有限制一并写清。主视口只用来说明使用场景，走查者可用不同尺寸窗口；窗口不同本身不算问题，主 Agent 不为此补做整套检查，只有问题确与尺寸相关才在主视口复现。⛔ 给原始 `TASK.md`、具体用户案例、预期操作路径、源代码、设计说明、历史问题。

派发话术：

`读 references/ux-reviewer.md，按【轻量 UX 走查】执行。只通过真实页面理解产品与用户目标，自选一条主路径操作，记录观察到的体验障碍。页面地址、主视口与必要测试材料如下；窗口可不同，仅尺寸相关问题需在主视口复现。`

模板路径换成本 Skill 目录的绝对路径。子 Agent 必须能操作真实页面；只能看截图或源码时改交静态走查并标明，⛔ 说任务已走通。它给出的产品理解、任务与路径是它自己的观察，不是主 Agent 预置的脚本。

走查记录里要留下这次隔离调用的身份痕迹（子 Agent ID／会话 ID／运行目录）与证据放在哪；宿主不给标识，就留一份能分清主 Agent 和评审者的独立上下文与操作记录。要是只有主 Agent 自己的说法、查不到独立执行者，就按自检算，如实写「未完成独立 UX 走查」，⛔ 说成子 Agent 已经评审过。

## 收报告后

先把每条问题归三类：可复现的产品问题／测试工具或数据问题／仍待验证的推测。先排除后两类，⛔ 用制作意图反驳观察。保留实际路径与证据，修的是入口、反馈、上下文与恢复方式，⛔ 只补一段说明。

走查修正后⛔ 强制再派；主 Agent 自己完成保存、刷新读回、失败恢复等功能验证——评审报告不能替代这一步。UX 子 Agent 只能发现可观察的操作障碍，不代表真实用户，⛔ 据此推断真实用户的成功率、满意度或耗时。
