# 任务过程工作区

> 归属：约束满足闭环 · 第 7 步「交付」前的工作区与证据核对。
> 过程文件与正式交付必须分开。`.vudgio` 是项目里的本地工作区：既不是交付目录，也不是第二套设计规范。

## 谁优先

- 用户指定的输出路径、项目既有约定排在最前。项目已经规定 `_work/`、`shots/` 之类过程目录，就沿用，⛔ 另建 `.vudgio`，也⛔ 搬旧文件。
- 没有约定时用 `<项目根>/.vudgio/<任务名>`。任务名取简短可辨的；撞上别的任务就加后缀，⛔ 覆盖。
- 正式代码、测试、最终文档、线上资产写回用户项目；页面、构建配置、样式、脚本⛔ 引用 `.vudgio`。
- 凭据、未脱敏数据、令牌⛔ 入工作区；历史任务不自动清，删除／迁移／外传先要授权。

## 开工

先读项目的 `AGENTS.md`、`DESIGN.md` 或同类规范，再决定工作目录；没有这些文件不影响开工。确定要用 `.vudgio`，才准备下面的目录；项目已有别的过程目录约定就不创建它。

`.vudgio` 已存在但不是目录，或是指向别处的符号链接：⛔ 往里写，说明冲突交用户定。是普通目录就复用，不清空；一个任务一个子目录，续作同一任务才复用该子目录。

用 `.vudgio` 且 `.gitignore` 不存在时，写入：

```gitignore
*
!.gitignore
```

它只忽略过程文件，⛔ 动项目根那份 `.gitignore`。已有这个文件但内容不同：保留原文，并告诉用户过程文件可能出现在 Git 状态里。需要提交的证据或文档明确放到项目正式位置，⛔ 改忽略规则。

## 过程文件的落点

按实际需要建子目录，⛔ 为形式整齐建空目录：

- `explore/`：候选方案、调研、未确认的设计草稿、临时小样。
- `assets/`：原始素材、中间变体、素材缓存。
- `shots/`：截图、录屏、评审证据。
- `logs/`：命令日志与临时输出。

需要长期保存的正式测试、设计规范、交付文档⛔ 藏在这里。进行中的迁移状态留任务目录；规范条目的确认与推断按存量项目的规则标记，⛔ 把推断写成用户确认。

## 命令从哪跑、输出去哪

不是所有工具都一律从任务目录跑。按页面资源与 HTML 引用基准定命令目录，过程输出统一落任务目录。显式 `--out`、`--dir`、`--cache` 及其他输出参数始终优先，⛔ 二次解释。

- **截图与录屏**：`--root <项目根>` 定静态服务范围，`--out .vudgio/<任务名>/shots` 定输出。这样嵌套页面仍能加载项目共享资源，截图留在工作区；`--root` 只决定服务范围，不决定截图落点。
- **素材检索**：在任务目录跑 `curate_media.mjs`，`assets/` 与 `.curate-cache.json` 默认留在原处。显式 `--dir` 指向别处时，工具可能回退读该目录或父目录的缓存；要任务隔离就同时给本任务的 `--cache .curate-cache.json`，要共享才复用旧缓存。
- **对比页**：候选放任务目录的 `explore/`，`build_explorer.py` 默认把 `style-explorer.html` 生成在旁边。
- **生图**：结果要成为页面资产时，`--out` 直接写正式资产目录。
- **图片处理**：要复制正式 `srcset` 时，从项目根跑 `prep_image.mjs` 并输出到正式资产目录。它给的片段按命令目录计算，⛔ 从任务目录把相对路径抄进正式页面。

工具选项见 [工具](tools.md)。中间原图可以留工作区，但最终 HTML 及其依赖只许引用项目正式位置的文件。

## 接着做老项目

未确认的方向草稿、进行中的迁移状态留工作区。项目已有设计规范文件的读取、确认、推断标记、更新与入口，按那个文件与项目约定执行；⛔ 把过程草稿当项目规范，也⛔ 另写一套重复规则。

## 交付前核对

核对最终改动，⛔ 只看命令成功没有：

- `git diff` 里只有正式交付、必要的规范更新、用户要求的文件。`git status` 中的过程文件只能以未跟踪项保留，⛔ 进提交；`.vudgio/.gitignore` 属允许保留的工作区配置。
- 忽略规则不同、过程文件出现在未跟踪项时：列出来说明，⛔ 为消掉提示而删除、迁移或改写规则。
- 正式代码与页面里没有 `.vudgio` 引用，所引资产都在项目正式位置。
- 项目根没有意外新增的候选、截图或缓存；旧文件没被移动或删除。
- 交付说明给出正式文件与工作区证据的位置，并跑项目相应的检查。

现有约定与工具够用时，⛔ 新增目录管理程序。只有真实任务反复出现建错目录、覆盖任务或误交付，才考虑把初始化与检查做成脚本。
