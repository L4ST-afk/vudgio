## 一、起点说明

导航是用户在微小屏幕上理解信息空间位置的地图。移动端导航必须将“顶级入口、次级分支、深度下钻与临时支线”严谨分层。（自研）

## 二、移动端四大经典导航模式约束

| 模式名称 | 核心适用场景 | 关键约束 |
|---|---|---|
| 标签栏导航（TabBar / BottomNav） | 3–5 个一级核心业务空间，常驻屏幕底部自然舒适区 | 槽位严格限定为 3 到 5 个；少于 3 个浪费横向空间，多于 5 个会导致单项触控热区低于 `44pt`，极易发生手指误触 |
| 顶部切换栏（Top Segmented / Scrollable Tabs） | 单一模块内的平级业务视角切换（平铺 2-4 项或横向可滑） | 2–4 个固定分类使用分段控制器等分平铺；5 个以上使用水平可横滑 TabBar |
| 栈式层级下钻（Hierarchical Navigation Stack） | 从列表点击条目，新页面从右向左滑入（Push），左滑退回 | Push 从右向左滑入，左滑退回 |
| 浮动半屏抽屉（Modal Bottom Sheet） | 临时调起支线任务（如筛选面板、分享面板、多属性规格选择） | 临时支线任务调起 |

### 1. 底部标签栏（TabBar）硬门禁约束

- 槽位数量：严格限定为 3 到 5 个。少于 3 个会浪费横向空间，多于 5 个会导致单项触控热区低于 `44pt`，极易发生手指误触。（自研）
- 图标与文字组合：优先采用“图标上、文字下”或“纯图标配微文字提示”的组合。文字严禁超出 4 个汉字。（自研）
- 徽标计数（Badge）：高时效性沟通（IM 聊天）使用红色具体数字（超过 99 显示 `99+`）；普通系统推送或活动更新使用 `8px` 纯色小红点，严禁滥用数字给用户造成清理压力。
- 深层页面隐藏 TabBar：当用户进入第二级、第三级详情下钻页时，必须隐藏底部 TabBar，将完整的屏幕垂直视野与底部安全区让渡给当前子页面的内容或主 CTA 按钮。（自研）

### 2. 顶部切换栏（Top Tabs）选型判据约束

- 2–4 个固定分类：使用分段控制器（Segmented Control）等分平铺，整个容器带轻量微底色和滑块切换动画。
- 5 个以上长分类：使用水平可横滑 TabBar（Scrollable Tabs），必须保证当前选中的 Tab 自动居中对齐，并在左右两端设置微弱的渐变蒙层，视觉暗示“后面还有内容可滑”。

## 三、手势交互设计体系约束

手势是零界面占用的交互捷径，但全部效率都建立在用户知道它存在的前提上。（自研）

### 1. 手势设计的四类高频策略约束

| 策略类型 | 交互表现 | 典型落地场景 | 核心设计约束 （自研）|
|---|---|---|---|
| 单手操作补偿 | 双击局部放大、双击滑动缩放、长按倍速 | 地图缩放、视频全屏单手操作控制 | 必须向下兼容常规双指缩放操作 （自研）|
| 多段式手势递进 | 持续按压时长或滑动距离达到阈值后功能跃迁 | 长按点赞触发连赞/收藏；持续下拉突破阈值进入“二楼” | 达到阈值时必须触发震动触觉反馈（Haptic Feedback） |
| 行内快捷滑块 | 列表条目向左轻扫露出一组功能按钮 | 消息列表“标为已读/删除”、邮件归档 | 滑出区域宽度控制在 `70–140pt`，必须带明确操作确认 （自研）|
| 沉浸式自动避让 | 页面向上滚动阅读时导航栏平滑收起 | 新闻详情长阅读、商品详情流 | 只要用户有轻微的“向下反拉”动作，导航栏必须立即重新浮出 （自研）|

### 2. 手势的不可发现性与适老底线约束

- 手势只能当提效捷径，严禁作为唯一功能入口：删除、编辑、收藏等核心功能，界面中必须存在可视化的点击按钮；手势只服务于熟练用户。（自研）
- 适老模式硬规则：在面对银发族或大字版模式时，彻底禁用复杂多段手势与行内横扫手势，所有操作全部还原为大号实体按钮。（自研）

## 四、橡皮筋弹性阻尼与过度滚动治理约束

### 1. 弹性拖拽曲线物理公式

iOS 经典的橡皮筋阻尼效果能够给用户清晰的“拉到尽头但仍有弹性物理反馈”的高级质感。其阻尼位移位阶满足非线性渐近函数：（自研）

$$x = x_0 + \left(1 - \frac{1}{\frac{x - x_0}{d} \times c + 1}\right) \times d$$（自研）

- d 为屏幕物理尺寸（通常为屏幕高度）；
- c 为阻尼系数（通常取值在 `0.55` 左右）；
- 拖拽距离越大，手指移动时元素位移越迟缓，直至在物理极值处平滑锁止。（自研）

### 2. Web 移动端滚动穿透与白边阻断约束

根视口与列表容器需分别声明 `overscroll-behavior` 与 `touch-action`，以阻止页面弹性下拉露出浏览器底层白色背景与下拉刷新假死，并防止横滑连带触发整页垂直晃动：

```css
/* 阻止页面弹性下拉时露出浏览器底层白色背景与下拉刷新假死 */ /*自研*/
html, body {
  overscroll-behavior-y: contain; /*自研*/
  -webkit-overflow-scrolling: touch; /*自研*/
}

/* 列表局部横滚容器，防止横滑连带触发整页垂直晃动 */ /*自研*/
.horizontal-scroll-container { /*自研*/
  overflow-x: auto; /*自研*/
  overflow-y: hidden; /*自研*/
  touch-action: pan-x; /*自研*/
  overscroll-behavior-x: contain; /*自研*/
}
```

### 3. iOS 边缘滑动手势保护约束

- 致命冲突：在 iOS 页面最左侧区域放置了横向轮播图（Swiper / Carousel）或横滑卡片组时，用户试图通过屏幕边缘右滑返回上一页，极易被内部轮播图劫持，导致无法顺利退出页面。
- 工程解法：页面最外层边缘留出至少 `16pt` 的安全触摸间距，或者在轮播图组件上配置只在 `deltaX > threshold` 且非边缘起始时才响应手势。

## 五、达成判据与三态结论

下列判据可直接用于验收，每条带可执行的检查点：

| 判据 | 检查点 / 命令 | 阈值 |
|---|---|---|
| TabBar 槽位数量 | 检查底部标签栏槽位数量 | 3 到 5 个 |
| TabBar 文字长度 | 检查 TabBar 文字 | 严禁超出 4 个汉字 |
| Badge 数字上限 | 检查 IM 聊天徽标数字 | 超过 99 显示 `99+` |
| Badge 小红点尺寸 | 检查普通系统推送小红点 | `8px` 纯色 |
| 深层页面 TabBar 隐藏 | 检查第二级/第三级详情页是否隐藏底部 TabBar | 必须隐藏 |
| 分段控制器适用范围 | 检查 2–4 个固定分类的容器 | 分段控制器等分平铺 |
| 可横滑 TabBar 选中居中 | 检查 5 个以上长分类 TabBar | 当前选中 Tab 自动居中 |
| 单手操作补偿兼容性 | 检查双击局部放大等手势 | 必须向下兼容常规双指缩放操作 |
| 多段式手势阈值反馈 | 检查达到阈值时的震动 | 必须触发震动触觉反馈（Haptic Feedback） |
| 行内快捷滑块宽度 | 检查列表条目向左轻扫滑出区域 | `70–140pt` |
| 行内快捷滑块确认 | 检查滑出功能按钮 | 必须带明确操作确认 |
| 沉浸式自动避让反拉 | 检查导航栏在向下反拉时的表现 | 必须立即重新浮出 |
| 手势唯一入口禁令 | 检查删除/编辑/收藏等核心功能 | 必须存在可视化的点击按钮 |
| 适老模式手势禁令 | 检查银发族/大字版模式 | 彻底禁用复杂多段手势与行内横扫手势 |
| 阻尼系数 c | 检查橡皮筋阻尼系数 | 通常取值在 `0.55` 左右 |
| 滚动穿透 CSS | 检查 html, body 的 `overscroll-behavior-y` | contain |
| 横滚容器 touch-action | 检查 `.horizontal-scroll-container` | `touch-action: pan-x` |
| iOS 边缘手势安全间距 | 检查页面最外层边缘安全触摸间距 | ≥ `16pt` |
| 轮播图手势判定 | 检查 `deltaX > threshold` 且非边缘起始 | 已配置 |

三态结论：每条判据分为「过 / 不过 / 证据不足」。缺画面或缺材料一律记为「证据不足」，不得直接判「过」。
